# minecraft_mode

Fabric mod for Minecraft Java **26.3**. Mod id `minecraft_mode`, package `com.minecraftmode`. See README.md for content.

## Toolchain

- JDK 25 required (`C:\Program Files\Eclipse Adoptium\jdk-25.0.4.101-hotspot`, set as machine JAVA_HOME).
- Loom plugin `net.fabricmc.fabric-loom` (non-remapping). 26.x is unobfuscated: **Mojang names, no mappings, `implementation` not `modImplementation`, `jar` not `remapJar`.**
- Fabric API uses Mojang-style names since 26.1 (`CreativeModeTabEvents`, `FabricBlockLootSubProvider`, `FabricTagsProvider.BlockTagsProvider`, `ModelLayerRegistry`, ...).
- Verify APIs against decompiled sources (`./gradlew genSources`) instead of guessing; many 1.21 names changed (e.g. `Identifier`, `EntityTypes`, `ContextIntProviders`, `Feature` replaces `ConfiguredFeature`, blocks have no codec).
- 26.x worldgen: statuses are merged (`TERRAIN` = noise + surface + carvers) and from then on chunks only keep the final heightmaps; `*_WG` heightmaps are stale/unprimed during decoration, and `ChunkAccess.getHeight` already returns the top block's Y (no `- 1`). Worldgen code that needs column heights should scan the column (see `CityGenerator.shapeTerrain`).
- Client gametests run at render distance 5. For wide shots raise both `options.renderDistance()` and `PlayerList.setViewDistance`; chunk sending is still slow, so prefer fixed waits over `waitForChunksRender` there (`CityChecks` also writes a top-down `city_map.png`).
- 26.x client: GUI code uses `GuiGraphicsExtractor` (`extract*` methods instead of `render*`), screens open with `minecraft.gui.setScreen`, input is SDL (`InputConstants.KEY_*`, `Type.KEYBOARD`; no GLFW on the classpath).

## Layout

- `src/main` — common code. `registry/` (blocks, items, effects, entities, tabs, tags, particles, menus, components, attachments), `entity/`, `economy/` (shop merchant, offers, wallet), `consumable/` (the 58 consumables and their buffs), `enchantment/` + `worldgen/` (bootstraps used by datagen; `worldgen/lair/` named lairs), `job/` (class system, `job/quest/` advancement trials, `job/gear/` class armor and stat totals), `loot/` (shop split, drops, ether, evolution), `entity/named/` + `entity/boss/` (named monsters, raid bosses), `raid/` (raid dimension, arenas, parties, instances, loot sessions), `city/` (the capital at 0, 0), `progress/` (reset cycle, records, achievements, titles, collection bonuses), `bounty/`, `enhance/`, `market/`, `talent/`, `companion/` (pets, mounts), `craft/` (professions, recipes, herbs, stations, crops, fish), `dungeon/` (dungeon dimension, runs, keystones), `event/` (world events, `MobPower` in `entity/`), `story/` (main story), `bag/` (bags, trash), `residence/` (residence dimension, land claims), `travel/` (the waymaster's destinations), `admin/` (the admin screen's server side), `network/`, `command/`, `mixin/`.
- `src/client` — renderer, model layer, **datagen providers** (`client/datagen`), `client/map` (minimap + world map: `MapData` explored colours per world/dimension saved under `<gamedir>/minecraft_mode/map` — keyed by the save folder plus a name hash in singleplayer, the address on servers (`MapClient.worldKey`; older display-name maps are copied over once), `TerrainScanner`, `MapTexture` GPU windows created lazily — never touch the GPU in static init, datagen runs the client entrypoint, `Waypoints` JSON (the server adds one with `MapMarkPayload`, e.g. the lair map's find, and the next big map opens there: `MapScreen.focus(x, z)`), `FieldBosses` (named monsters, mini-bosses and bosses the client sees, minus training dummies, plus the titan the server reports every second in `FieldBossPayload`; pinned to the minimap's edge when outside), `MapScreen`/`WaypointScreen`, keys M and comma).
- `client/hud` — `VitalsHud` (HP and MP bars over the left half of the hotbar in place of vanilla `HEALTH_BAR`/`ARMOR_BAR`, armor points beside MP; the class panel then drops its MP row; `/hpbar false` in `ClientSettings` brings the hearts back), `TooltipLayout` (wraps tooltip lines wider than half the screen, registered last, render thread only; tooltips taller than the screen start at the top and scroll with the wheel through `GuiGraphicsExtractorMixin`). Tooltip callbacks also run off the render thread with no player: the recipe book and creative search build every item's tooltip on a background thread, so they must never touch the font (it bakes glyphs into the GPU atlas) or client caches there (`JobTooltips.viewer()`); until 0.5.19 a Korean recipe book search crashed the game, `TargetHealthHud` (last hit monster's bar, top centre between the class panel and the minimap, under boss bars; the server names the target with `TargetHealthPayload` from `CombatHooks.afterDamage`), `TrashButton` (inventory "Bin" button -> `TrashPayload` -> `bag/Trash`, one undo), `BagTooltips`.
- `light/HeldLight` — a lit block item in either hand lights the player's surroundings with an invisible `minecraft:light` block the server moves along (air/water only, removed on move, logout, death, dimension change).
- Keybinds: R/X/V/Z skills, B innate, K class, I character (`client/job/CharacterScreen`), N talents, J codex, U pets, H mount, Y raid loot, M map, comma minimap, semicolon adventurer's menu (`client/menu`). G, P, L, O are vanilla defaults in 26.3 (quick actions, social, advancements, friends) — do not reuse them.
- `src/main/generated` — datagen output, committed. Never hand-edit; change the provider and run `./gradlew runDatagen`.
- `src/gametest` — client game tests, run in the order of `src/gametest/resources/fabric.mod.json`; keep them passing after changes. A test's name is its class name without `ClientGameTest`, lower case: `minecraftmode`, `enchantment`, `normalworld` (city + natural terrain), `job`, `gearraid`, `economy`, `lair`, `endgame`, `content`, `town`, `multiplayer` (manual, never runs unless named). `./gradlew runClientGameTest -Ptests=job,town` runs only those (`TestSelection` makes the others return at once; never reorder or trim the list); `./gradlew runClientGameTestParallel` runs the whole suite in `-Pshards` (default 3) game clients side by side, balanced by `gameTestSeconds` in `build.gradle` (update it when a test's time changes a lot), about 8 minutes instead of 22 sequentially; it also takes `-Ptests`. Shard n plays in `build/run/clientGameTest<n>` (logs, screenshots). Every test ends its singleplayer block with `WorldClose.prepare(context, server)`: Fabric's client gametest API (6.0.8) races on `close()` — the deferred `Minecraft.disconnect` submits a blocking task to the server (`IntegratedServer.halt`) at the start of the tick phase, and a server that is behind schedule refuses fresh tasks (`MinecraftServer.shouldRun`) and parks on the phaser, so both threads wait forever (render thread in `executeBlocking`, server thread in `enterPhase`). Settle ticks do not fix it; `WorldClose` pushes the server's next tick deadline 2 s out so that tick has an idle window for the halt task. Keep it, and if a run still hangs after "Stopping singleplayer server as player logged out", take a thread dump (`jcmd <pid> Thread.print`) before killing it.
- Multiplayer test (manual, not in the suite): `MultiplayerClientGameTest` runs two scripted clients (`runMpAlice`, `runMpBob` in `build.gradle`, own game dirs, usernames Alice/Bob) against a real `runServer` (needs `run/eula.txt` agreed, `online-mode=false`, `white-list=false`, `enable-rcon=true`, `server-ip=127.0.0.1`). Start the server, then `./gradlew runMpAlice -PmpRcon=<rcon password>` and `./gradlew runMpBob` (both runs pick only `multiplayer`). Alice drives the server over RCON; the clients hand steps over with flag files in `build/mp`. Restore `server.properties` afterwards.
- `tools/TextureGen.java` (+ `tools/ClassArt.java`, `tools/QuestArt.java` for trial tokens and trainer/NPC skins — every `CityNpc.Role` needs one, `ContentClientGameTest` checks, `tools/EndgameArt.java` for endgame items and lair chests, `tools/ContentArt.java` for herbs, crystal, shard, keystone and station blocks) — draws every texture except class weapons from scratch (no vanilla assets); run it instead of editing PNGs by hand. Class weapon textures are drawn at datagen time by `client/datagen/art` (`WeaponArtist`, `Shapes`, `Bows`) from each weapon's archetype, tier and `WeaponArt` colors; `runDatagen` also writes a review sheet to `build/weapon-preview.png`.

## Rules

- Content that is data-driven in 26.x (enchantments, ore features/placements, recipes, loot, tags, lang) goes through datagen, not hand-written JSON. Exception: `assets/minecraft_mode/equipment/mythril.json`.
- `ShopMerchant` is not an entity; `MerchantMenuMixin` must stay or shift-click trades crash the server.
- Gathering sells at flat prices (0.5.9): rare finds by how hard they are to mine (diamond 5S, netherite scrap 8S, mythril 12C), raw ores about 3/4 of their ingot, emeralds kept low (villagers hand them out). No shop may pay as much as any shop asks for the same item (`TownClientGameTest.checkShop`).
- Profession goods (0.5.12): `craft/CraftPrices` adds sell lines for every fixed-output recipe to its profession's shop (cooking -> grocer, alchemy + loose herbs -> alchemist, smithing -> blacksmith). Worth = raw materials (`ShopOffers.basePaid`, `CraftPrices.RAW` herbs/titan shard, `VANILLA` made vanilla items, made ingredients by their cheapest recipe) x `mastery(recipe level)`, cheapest recipe per item. Material worth never uses shop sale prices, so buying inputs from a shop and selling the product never pays. New recipes are bought automatically; new ingredients nobody buys count 0 until listed in `VANILLA`/`RAW`.
- Shop prices: base lists in `ShopOffers.trades(ShopType)`; market pressure lives in `MarketData` (world SavedData) and is applied through `MerchantOffer.setSpecialPriceDiff`. Keep `ShopType` ids and trade item ids stable — they are the saved market keys. Sales to shops are remembered by `MerchantResultSlotMixin` -> `economy/Buyback` (attachment `ModAttachments.SOLD`, last 10, exact stacks) and bought back at 1.5x through `BuybackPayload` (client `BuybackPanel` beside shop-titled merchant screens; the server checks the open menu is a `ShopMerchant` via `MerchantMenuAccessor`); buybacks never touch market pressure.
- 26.3 reads natural spawns from the `NATURAL_MOB_SPAWNS` environment attribute; `NormalWorldClientGameTest` checks that Fabric `addSpawn` reaches it.
- Vanilla monsters never drop the weapons/armor they spawned with (`MobMixin` zeroes non-preserved drop chances for `minecraft:` types at death); what they picked up or were handed (preserved slots) still drops. Gear comes from the mod's own drops.
- No creepers: `ModEntities` removes them from every biome's spawn list and `NaturalSpawnerMixin` refuses any that still come (structure overrides, datapacks). Trials, lairs and bounties must not need them; gunpowder and flight-3 rockets are sold in the general store.
- Enchantments: each set is a class in `enchantment/` (`WeaponEnchantments`, `RangedEnchantments`, `ToolEnchantments`, `ArmorEnchantments`, `LifeEnchantments`) with `EnchantInfo` (key + en/ko name + en/ko description) and a bootstrap built on `EnchantmentFactory`. Prefer data-driven effects; marker enchantments are read in code by `ToolEnchantmentHandlers`, `craft/Crops` and `craft/Fishing` (hoes, rods), `CombatEnchantmentHandlers`, `ArmorAuras`, `BowItemMixin` and the client `LightmapRenderStateExtractorMixin`. Lang/tags iterate `ModEnchantments.ALL`.
- Auras must never stack: one fixed transient modifier id per aura (`aura/<name>`), level = max over nearby sources. Buffs use the enchantment's own attribute ids, so buff + aura stack by design.
- `docs/ENCHANTMENTS.md` is kept by hand from `src/main/generated` (en/ko lang + max levels; no datagen provider writes it): update it after changing enchantments.
- HUD panels on the left edge report their area with `BossBarLayout.reserveLeft` (`JobHud` starts each frame); `BossBarLayout` moves the vanilla boss bars right of them, or below when there is no room beside them, the minimap (`MinimapHud.box`) or the effect icons; `TargetHealthHud` goes under `BossBarLayout.bottom()`.
- After a change: `runDatagen` (if data changed) → `build` → the tests that cover it (`runClientGameTest -Ptests=...`) while iterating → the whole suite (`runClientGameTestParallel`) before committing, and look at the screenshots.

## Class system (`job/`)

- `JobClass` (7 classes x 4 tiers, titles + passives in en/ko; append new classes at the end — the network codec uses the ordinal), `JobData` (player attachment `ModAttachments.JOB`: class, tier, level, exp, MP, cooldowns; synced to the owner, kept on death), `JobProgression` (exp curve, tier levels 10/25/45/70; `advance` only checks level — items are the trial's job), `JobStats` (max MP/regen, attribute modifiers from level, passives and the held weapon's engravings), `JobEvents` (exp/essence from kills and ores, MP tick, Avalon, death penalty).
- Content: one file per class in `job/content/` built with the `ClassContent` DSL (`weapon(...)` + `skill(...)` + `Actions.*`). Startup validates tier/level ranges and skill counts (3 per weapon, 4 at tier 4); ids are saved item/cooldown keys — never rename them. Tooltips, lang and docs are generated from these definitions.
- Skills: `job/skill/Actions` holds every building block with its own tooltip template (`Actions.texts()` -> lang). Add new behavior there, not in content files. Damage from skills/shots goes through `CombatHooks.deal` with a `DamageKind`; `LivingEntityMixin` feeds `CombatHooks.modifyIncoming` (passives, engravings, marks, stances, vulnerability). Delayed steps use `SkillScheduler`; `SkillContext.valid()` must be checked in delayed code. Every `barrage` projectile flies at the crosshair, so one target takes count × mult: keep that close to the tier's other skills (0.3.4 retuned the outliers). Skill summons carry their caster (`Actions.summoner`): raid bosses take their damage and `Contribution` credits the caster.
- Crits, areas, summons (0.4.0): `CombatHooks.outgoing` rolls crits for basic hits, shots and `DamageKind.SKILL` (CRIT_REFUND stays basic-only); skill summons (`Actions.markSummon` tags the caster and power) hit for power x `Actions.Summon.share` through `CombatHooks.modifyIncoming` like skills. Area hits go through `SkillContext.hitArea` (each target gets `areaShare`: full up to `AREA_FULL` = 5, then sqrt(5/n)) and their factories apply `SkillContext.AREA_SCALE` (0.85) to the listed multiplier, shown in tooltips. New area actions must do both. Every damaging action reports `SkillAction.estimate(targets)` (attack/move overloads, `estimated`), which `ClassDocProvider` turns into the 1/5-target columns and the "스킬 피해 비교" section. `ProjectileAction`: even fans get a middle shot (`shots`, `each`), `parallel(width)` sends shots side by side, non-arcing shots aim at the cast target (aim assist), and the homing shots of one fan split the enemies between them (`SkillProjectile.Volley`, the middle shot keeps the crosshair enemy), so a lone target takes one shot as `estimate` counts. `Actions.lifesteal` only heals off the skill's own hits; a buff skill without hits uses `lifestealFor` (timed, `CombatState.lifesteal`, every hit). Percent and flat cooldown cuts together stop at `SkillCaster.MAX_COOLDOWN_CUT` (60%). `CombatHooks.showHit` sends `TargetHealthPayload` + `DamageNumberPayload` (client `hud/DamageNumbers`, `/damagenumbers` in `ClientSettings`). Training dummies (`entity/TrainingDummy`, armor-stand bodies that are `Enemy`, the boss kind `EliteMob`) never take damage, call `modifyIncoming` and the AFTER_DAMAGE event themselves and report to `city/DummyMeter`; `CityServices.keepDummies` keeps `CityZone.dummies` in the warrior arena: a post keeps the dummy on it, an empty post takes the nearest stray of its kind in `CityZone.dummyArea` (new one only when none), strays go back once not hit for `DUMMY_RETURN_TICKS` (`TrainingDummy.hitWithin`), extras are removed (until 0.5.16 a moved dummy got a twin and they piled up).
- A class weapon is "active" only when class, tier and level all match (`JobWeapons.isActive`); otherwise it is a plain weapon (basic attack/shot only, no skills, no engravings).
- Aiming and hits: `SkillContext.lookPoint` stops only at blocks (beams pass through monsters); skills placed where the caster aims use `groundPoint`/`aimPoint`/`SkillContext.aimed`, which stop at the first enemy in the crosshair. `SkillContext` keeps the view and that enemy from the moment the skill started (`aimedEnemy`), so delayed and repeated area steps land where the caster aimed, following that enemy; `barrage` lobs projectiles with gravity onto the target (`Actions.lob`). `SkillProjectile` sweeps its next move (`SkillProjectile.reach`, radius `ProjectileStyle.hitRadius`: sword waves 0.75, the rest 0.3) before vanilla's check, because vanilla never hits a hitbox the projectile starts inside (a monster pressed against the caster) and has no margin for the first ticks; `AbstractArrowMixin` adds the same reach to class arrows (`CombatHooks.classArrow`), and `CombatHooks.modifyIncoming` lets them through the damage cooldown like every other shot. The extra projectiles of a basic shot (`EXTRA_SHOT`, cap 4) hit each enemy once (`BasicAttacks.Fan`, shared by the shot's class arrows through `AbstractArrowMixin.canHitEntity` and by its `SkillProjectile`s, blasts included), so a lone target takes one as `ClassComparison` counts; 0.5.10 stopped whole fans landing on raid bosses. Instead each extra projectile adds `BasicAttacks.EXTRA_SHOT_DAMAGE` (4%) basic shot damage in `shotBonus`, a steady 1-target worth whatever the target's size. `rain` drops each projectile on a random enemy inside its circle (led by its walk) and starts it under any roof (`Actions.sky`), so its multipliers are per projectile on one target. Portals and blades launched beside the caster start at `SkillContext.openPoint` (never inside walls or low ceilings). Class projectiles (`CombatHooks.classProjectile`) ignore vanilla's projectile immunities (`EndermanMixin`, `WitherBossMixin`, `ShulkerMixin`, `DragonSittingPhaseMixin`, `ProjectileDeflectionMixin` for breezes); `SkillProjectile` damages the Ender Dragon through its parts.
- Engravings: `Engraving` enum (per class, optional archetype filter), stored in the `ModDataComponents.ENGRAVINGS` item component (max 3 lines on weapons, 4 on class armor with per-slot armor engravings; duplicates stack, caps in `EngraveStat`). The `EngravingMenu` (engraving table) charges essence from the inventory; condensed essence = 9.
- Guild shop offers depend on the visitor (`ShopOffers.trades(ShopType, Player)`); trade keys stay stable for market pressure.
- `docs/CLASSES.md` is written by `ClassDocProvider` during `runDatagen`; do not edit it by hand.
- `JobClientGameTest` casts every skill of every weapon once (and checks each summon step's helpers are still there); keep it passing when adding or changing skills.
- Skill summons are never kept: `JobEvents` refuses tagged ones read from disk through `ServerEntityEvents.ALLOW_LOAD` (`fromDisk`). Never use `ENTITY_LOAD` for that: it also fires for fresh spawns, and until 0.5.15 it removed every summon the moment it appeared.
- Skill balance (0.4.4): in each tier a weapon's skills add up (damage per cast ÷ cooldown, 1 target, as in CLASSES.md "스킬 피해 비교") to about 0.7–1.4× the tier's weapon median (support weapons may sit lower); one skill stays under about 2× the skill median for 1 target and 2.5× for 5; ultimates hit 450–1000% per cast at 45–60 s (less when they also shield or buff) and 1100–1300% at 75–90 s. Check new or changed skills against those numbers after `runDatagen`.
- Skill share (0.5.3): skill multipliers are of `WeaponDef.skillPower()` (power × `SKILL_POWER` = 1.5), basic attacks and shots hit for `attackDamage()`/`shotDamage()` (archetype multiplier × `BASIC_POWER` = 1.0). Skills carry about 20–55% of a class's 1-target damage ("스킬 비중" in CLASSES.md "직업 비교") while a basic hit stays about half a normal skill hit (the user wants both: skills that matter and basic hits that are not tiny next to them). Change those two knobs, not the 539 skill definitions, to move the split. Skill tooltips show "1회 피해 약 N" (`SkillCaster.castPower` × estimate) because players read the percentages as damage.
- Class balance (0.5.1): CLASSES.md "직업 비교" (`client/datagen/ClassComparison`) estimates each class's damage and survival at the last level of every tier from the real definitions (passives, level rewards, vitality, the best armor set, talents spent for damage; no engravings, random options, enhancement or skill support effects). Keep every class's 1-target total within about 90–110% of the mean at each level; survival may differ by role (warrior/hunter tanky, archer/mage fragile, archer a glass cannon up to ~110%; 0.5.13 put it at 106–108% in every tier through Eagle Eye and its sets). Rule passives the calculator copies (`BasicAttacks.BABYLON_CHANCE`/`EAGLE_EYE`/`EXTRA_SHOT_DAMAGE`, `SkillCaster.ARCANE_MASTERY`/`AKASHIC_RECORD`, `BasicAttacks.shotBonus`, the rogue/warrior/archer numbers in `CombatHooks`) must stay in step with it. MP never runs out in a minute of fighting, so MP stats are not damage.
- Melee and the hurt cooldown: a fully charged swing (`CombatState.fullSwing`, set by `PlayerMixin` around `Player.attack`, vanilla's > 90%) of a class weapon resets the target's hurt cooldown in `CombatHooks.modifyIncoming`, like shots and skills, so attack speed above 2/s counts and a skill hit or double strike never swallows the next swing; uncharged spam still bounces.

## Trials and trainers (`job/quest/`, `entity/ClassTrainer`)

- Choosing a class and every advancement goes through that class's `ClassTrainer` (no advance button). `Quests` defines the 28 trials (`<class>_<tier>`) and their 28 trial tokens. Tier 1 is `QuestDef.instant()` (no goals, tokens or materials): accepting it at level 10 advances on the spot, and its token no longer drops but stays registered. Tiers 2-4 are real trials = kill goals + token count + materials (always essence; tier 3/4 also need a golem/boss kill). Quest and token ids are saved keys — never rename them.
- `QuestData` (attachment `ModAttachments.QUEST`, synced to the owner, kept on death): active trial id, kill progress, `visitedCity`. `QuestService` holds the rules (status per trainer, accept/complete/abandon, kill credit on `AFTER_DEATH`); screens read the same synced data. Tokens only drop for a player whose trial needs them and go straight into the inventory; bosses (`Quests.BOSSES`) credit everyone with the trial within 64 blocks.
- Trainer actions come in as `QuestActionPayload` and need the trainer within 8 blocks; right-clicking a trainer sends `OpenTrainerPayload` (client `TrainerScreen`).
- Trial lang (trainer names/greetings, trial texts, tokens, guide book) lives in `client/datagen/TrialLang`; `ClassDocProvider` writes the trial table into `docs/CLASSES.md`.

## The capital (`city/`)

- Stormhold is generated at 0, 0 in the overworld of noise worlds only (flat test worlds have none). `ChunkGeneratorMixin` calls `CityGenerator` during decoration: chunks inside `CityZone.CORE` are flattened to `CityZone.baseY` (median natural height, cached per seed) and built; vanilla features/structures there are suppressed except ores; a `BLEND` ring eases terrain back. Every write goes through `Build`, which clips to the chunk being decorated — buildings must be pure functions of coordinates (no randomness that differs per chunk, no reading neighbour chunks).
- Districts: `CityCore` (roads, plaza + fountain, walls, gates, lamps), `CityNorth` (keep + raid gate, mage tower, Enchanter's Hall, warrior arena, Hunter Association), `CityMiddle` (old town + rogue Shadow Hall, cathedral, homes), `CitySouth` (archer park + Urahara Shop, market + alchemist + Adventurers' Guild with shops/engraving tables, forge, harbor + pirate ship). Trainer posts are `CityZone.trainerHome`; `CityServices.keepTrainers` (every 100 ticks) spawns missing trainers, removes duplicates and brings wanderers back. The hall's four enchanting tables (15 bookshelves each, level 30), the grindstone in the opening of each table's ring (`CityZone.grindstones`, never between table and shelves; `CityServices.keepGrindstones` adds them to older cities) and the city anvils are listed in `CityZone.enchantingTables/anvils`; `CityServices.keepAnvils` replaces worn anvils because nobody can place blocks in the city.
- Training Grounds (`city/TrainingGrounds`): a sealed hall at dy -18..-9 under the south-east park, built by the generator like the districts (stairs from a pavilion at x 22..24, z 12..17). While a classless player is inside, monsters tagged `TrainingGrounds.TAG` step out of the alcoves (cap grows with trainees), classless killers get double class EXP (`JobEvents`), the guards skip them only inside the hall, and they are removed when nobody trains.
- Multiplayer-first: world spawn is the plaza (respawn radius 0); first join teleports there and gives the guide book. Inside the walls (`CityZone.inside`) the city is a safe zone: no hostile natural spawns (`NaturalSpawnerMixin`), city guards (`CityServices.driveOffHostiles`, every second) remove hostile mobs that get in anyway (climbing spiders, cave wanderers, eggs; skill summons and NoAI mobs are exempt), no building/breaking for non-op survival players (`PlayerMixin`, `BlockItemMixin`), no PvP (`CombatHooks`), no explosion block damage (`ServerExplosionMixin`), and food/saturation stay full (`CityServices.feedResidents`, every tick).
- Outskirts (`CityZone.outskirts`, up to `OUTSKIRTS` = 196 from the centre): no hostile natural spawns on the surface (top block - `OUTSKIRTS_SURFACE_DEPTH`), as if lit; caves below and animals still spawn (`CityServices.blocksSpawn`).
- `CityZone.isCityLevel` only works on the server. The client learns whether the overworld has the capital from `CityInfoPayload` (sent on join); the map draws Stormhold, every NPC/trainer post and the Training Grounds stairs from `client/map/CityPlaces` (big map: NPC tab, hover names, `MapScreen.focus`).
- `NormalWorldClientGameTest` runs `CityChecks` (layout, trainers, safe zone, district/trainer screenshots) before moving to natural terrain for the ore/spawn checks.

## Town comforts (`city/CityFixtures`, `city/Homestead`, `bag/`, `job/quest/TrialHunts`)

- `CityFixtures`: a lit Nether portal and an active End portal in the keep courtyard, 12 ender chests (`ENDER_CHESTS`), and the plaza travel circle (lodestone at `WAYSTONE`). Built by the generator and kept at runtime by `CityFixtures.ensure` (every 100 ticks, loaded chunks only, rebuilds the chunk around a missing piece) so older worlds get them too. Travel circles (plaza <-> homestead) are right-clicked (`useWaystone`) and cannot be broken.
- `Homestead`: flat land east of the walls (x `X0`..`X1`, |z| <= `HALF_Z`) flattened to the city floor by `CityGenerator` (core chunks = city square or homestead, `flatDistance`), no features or structures, a gravel road and a circle in the middle. It counts as outskirts (`CityZone.outskirts`, + `HOMESTEAD_MARGIN`). Building is allowed. Older worlds get it from `HomesteadLand` (world SavedData): once per world, one chunk per tick after start, `CityGenerator.reshapeHomestead` flattens only the plains and their blend ring (never the city core), then the road/circle; progress is saved so a finished world is never flattened again.
- Respawning is vanilla (world spawn is the plaza, beds override it); `TownClientGameTest` checks it.
- Bags (`bag/`): `BagItem` x3 (`BagKind` GEAR/SUPPLY/ORE — ORE is shown as the material bag and also takes enhancement stones, protection scrolls, awakening crystals and titan shards; ids are saved keys), contents in `minecraft:container`, `BagMenu` (generic_9x3, writes back on every change, the bag cannot move while open, no bags/shulkers inside). `ItemEntityMixin` routes pickups through `Bags.pickup` (never into a bag that is open on screen). Items handed out directly go through `Bags.give` (bags, then inventory, then the floor) or `Bags.giveOrMail` (the market mailbox instead of the floor: dungeon/raid rewards, raid loot) — never `placeItemBackInInventory` for rewards; both give a copy, so the caller can still name the stack. `Bags.fits` checks bag + inventory room (auction house). Currency/quest items (`BagKind.reserved`) never go into bags: shops, trainers and benches read the inventory. Crafting stations, bounty deliveries and the enhancement bench count and take through `Bags.count/take` (inventory first, then the bags); herbs go into the supply bag; lair chests shift-click into the bags first. Selling to a shop tops the payment slot up from the bags (`MerchantMenuMixin` sellFromBags: plain stackable items only, whole trades up to a stack), so gear never leaves a bag that way. Quartermaster Bram gives one of each once (`ModAttachments.STARTER_BAGS`); the general store sells them.
- Huntmaster Garrick (`CityNpc.Role.HUNT_MASTER`) -> `TrialHunts`: a private reinforced-deepslate arena in the dungeon dimension (x -4096, slots 128 apart; `Dungeons` leaves its monsters alone via `insideAnyArena`) that spawns only what the active trial still needs (`TrialHunts.needs`: unfinished kill goals, token sources while tokens are missing; bosses one at a time; never the Ender Dragon). Spawning stops when nothing is needed, then the player goes back. Death there is handled by `Dungeons.fall`.
- `job/AdvanceKit`: every advancement gives a class weapon + 4 armor pieces of the player's bracket, once per class/tier (`ModAttachments.ADVANCE_KITS`).
- Gap-closing skills (`job/skill/Engage`): `SkillAction.moves()/damages()` are set by the `Actions` factories (`move(...)`, `attack(...)`, `wrap` for repeat/delay); `Skill.engages()` = both. Movement steps call `ctx.guard` (0.5 s no damage after arriving, blocked in `CombatHooks.allowDamage`; `RaidDamage` and bypass damage still land) and `SkillContext` staggers every target an engaging skill hits (stun 0.3 s, 0.15 s for `EliteMob`/`Quests.BOSSES`). New movement or damage actions must use those factories.
- Player armor: `LivingEntityMixin` sends players through `entity/combat/PlayerArmor` instead of vanilla `CombatRules`: the same slope as vanilla for small hits and the same 20-point cap, but the counted armor bends towards the floor (a fifth) instead of falling to it in a straight line, so big hits no longer fall off a cliff. Monsters keep vanilla armor. Anything that estimates player damage taken (`ClassComparison`) uses `PlayerArmor.fraction`.
- Class armor defense (`job/gear/ClassDefense`, per class factors): armor/toughness from `ArmorPieceDef.armor/toughness`, and `ArmorPieceDef.defenseLines` (a quarter of the set's `EngraveStat.PROTECTION`, `MAGIC_DEFENSE`, class `DODGE` and the mage's `MANA_SHIELD`) summed by `GearStats`. `CombatHooks.incoming` applies protection to every hit and magic defense to `entity/combat/MagicDamage.is` (the mod's `minecraft_mode:monster_magic` damage type, datagen; named BREATH/SPIKES and spell BOLTs via `Ability.magic`, `Attacks.hit(..., magic)`, `MobProjectile.magic`; vanilla magic types). Raid boss patterns declared with `RaidBoss.spell(...)` (breaths, curses, bolts, elemental blasts) are magic too: their circles, rings, strips, cones, rain and volleys carry the flag (`RaidBoss.casting`, captured when the telegraph is placed; steps a spell schedules itself go through `asSpell`); claws, slams, charges and thrown rocks stay `pattern(...)` (physical). The mana shield (MP) and thorns/counter stance act only when a hit lands (`CombatHooks.landed`, `PlayerMixin` at the start of `Player.actuallyHurt`, before armor), never for hits dodged or guarded in ALLOW_DAMAGE, refused by another listener, bounced by the hurt cooldown or shrugged off (until 0.5.14 a dodged spell still cost MP). `ArmorStyle` only keeps names/sounds.
- Melee vitality: `JobClass.vitalityHealth/vitalityArmor` per tier, applied in `JobStats.refresh`. Vindicator melee is a flat `CombatHooks.VINDICATOR_DAMAGE` (5) before armor on every difficulty.
- Invasions scale from `WorldEvents.invasionPower` (defenders' average level - 5), `partyScale` (capped at `INVASION_PARTY_CAP` defenders), `invaderDamage` (x `INVADER_DAMAGE`) and `invaderCount`.
- `TownClientGameTest` covers the flat-world parts; `CityChecks.checkFixtures` covers portals, chests, circles, Garrick and the homestead.

## Residence (`residence/`)

- `ResidenceDimension`: `minecraft_mode:residence`, a flat plains stem on the vanilla `minecraft:overworld` dimension type (no own `DimensionType`; stem written by `RaidDimensionProvider`, grass at `SURFACE_Y`, `structure_overrides: []`). No hostile spawns (`CityServices.blocksSpawn`). `ResidenceTown` (called from `ChunkGeneratorMixin` at decoration, clipped per chunk like the capital) builds Stormhold's style there: the square (chunks within `SPAWN_CHUNKS` of 0, 0) is `CityCore.plaza` drawn through `Build.shifted` plus four corner towers, and four avenues paved like the capital's roads along chunk column/row 0 out to the world edge; both are public (`ResidenceDimension.isPublic`): no claims, no building. Plots between the avenues stay free-form.
- Getting there: the waymaster (`CityNpc.Role.WAYMASTER`, Waymaster Orin) west of the fountain, and a second one at the residence square (`ResidenceDimension.waymaster`, kept by `ResidenceRules` through `CityServices.keepNpc`). `travel/Travel` + `travel/Destination` is the general travel NPC: a right-click sends `OpenTravelPayload` with the places offered where the player stands (`Destination.offeredIn`), the client `TravelScreen` answers with `TravelPayload` (NPC within 8 blocks). New places = a new `Destination` (append: the ordinal is synced) with its `offeredIn` and `spot`.
- `LandClaims` (server SavedData): claims are 16x16x16 boxes — the deed user's chunk from the block under their feet up `SIZE` blocks. One owner per chunk column (extend up/down with more deeds), `MAX_CLAIMS` per owner, none within `SPAWN_CHUNKS` of the square. Trust lists are per owner (all their land). `Claim` fields and the saved shape are save data — keep them stable.
- `ResidenceRules`: inside a claim only owner + trusted may break/place/use blocks (any right-click, not just block-changing items) or touch non-monster, non-player entities; unclaimed residence land is not buildable at all; ops/creative are exempt (`CityServices.exempt`). Break/place go through `CityServices.blocksBuilding`; explosions break nothing there (`ServerExplosionMixin`). Crossing into other land shows the owner on the action bar (`label`), refusals say whose land it is.
- Border lines: `LandClaims.version` bumps on every claim/trust change; the HUD tick sends `LandBordersPayload` (every claim + its relation to the viewer) to residence players whose synced version is stale (so also on entering). Client `LandBorders` emits vanilla gizmos (`Gizmos.cuboid`, depth-tested) in `END_CLIENT_TICK` for claims within `RANGE`, plus an outline on top of the floor block so the edge shows on the ground.
- Nothing crosses a claim edge (`ResidenceRules.crosses`: different owner, unclaimed counts as one): fluids (`FlowingFluidMixin`), pistons (`PistonStructureResolverMixin`: head, pushed blocks and their targets, broken blocks), dispensers/droppers/crafters facing out (`DispenserBlockMixin`, `CrafterBlockMixin`), hoppers pushing out (`HopperBlockEntityMixin` on `ejectItems`, before Fabric's transfer API), fire spread/burn and lava ignition (`FireBlockMixin`, `LavaFluidMixin`). Player-caused damage (arrows, TNT) to protected entities is refused (`ResidenceRules.blocksDamage`: `ALLOW_DAMAGE` for living ones, `BlockAttachedEntityMixin` for frames, paintings, boats, minecarts).
- `LandDeedItem` (merit shop only, offer `land_deed`: `Bounties.DEED_MERIT` plus `DEED_RAISE` per deed bought before, counted in `BountyData.deeds` — abandoning refunds the item, not the count): use = claim, sneak-use or `/land` = `LandScreen` (client) via `OpenLandPayload`; `LandActionPayload` trusts online players by name, untrusts, abandons (`LandRestore`: the box goes back to `ResidenceDimension.natural` layers, entities in it are removed, container/frame/armor-stand items and the deed go to the owner). `ResidenceChecks` (run from `TownClientGameTest`) covers it.

## Economy, consumables and raids

- Coins never sit in the inventory: `Wallet` (attachment `ModAttachments.WALLET`, copper) deposits them every 10 ticks; `Coins.total/take/give` see wallet + inventory. Shops pay from the wallet through `MerchantMenuMixin` (fills the payment slots). `KEEP_INVENTORY` is forced on at server start.
- Essence is one currency (`economy/Essence`, condensed = 9): every essence cost (shops via `MerchantMenuMixin`, trials, profession recipes, engraving, enhancement) takes either kind and gives change as loose essence — check with `Essence.held`, pay with `Essence.take`. Profession recipes that make essence stay exact (no condense-for-change loop). Using essence condenses 9 → 1, using condensed essence breaks it (`item/EssenceItem`).
- Coin sinks scale with `GearShop.bracketPrice` (raid fee, engraving/reroll/removal, evolution, armor reroll), so they grow with level. Keep new sinks on that curve; coin sources too (gold-find procs pay `JobEvents.goldFindCopper`).
- `consumable/Consumables` defines the 58 consumables (`ConsumableDef`; the last 18 are cooking-only dishes of the mod's crops and fish, tiers 1-5; lasting effects are 10 minutes = `Consumables.LONG`); buffs are marker effects whose stats `BuffEffects` feeds into `GearStats`. Icons are drawn by `client/datagen/art/ConsumableArtist`. Item ids are saved keys. `docs/CONSUMABLES.md` is generated.
- Raid bosses declare their mechanics in `RaidBoss.mechanics()` (first at an HP fraction, then on an interval, never closer than `MECHANIC_GAP` = 45 s). Mechanic damage uses `RaidDamage` (bypasses armor and resistance, not totems/feather/Avalon). Team mechanics must scale their requirement with party size so solo players can clear them.
- Soul Reaper and Hunter passives, and the damage parts of Mage's, Rogue's and Pirate's (0.5.1–0.5.3), are stat lines in `job/gear/ClassPassives` (added up by `GearStats`); the rest of the first five classes' passives stay rules in `CombatHooks`/`JobStats`/`SkillCaster`/`BasicAttacks`. A mage's basic shots (orbs) also get the mage's skill damage (`BasicAttacks.shotBonus`).

Pets and mounts are never saved with the world (pet types `noSave`; mount types must stay serializable because players can only ride serializable types, so `MountEntity` refuses saving itself and always counts as saddled). ## Gear, named monsters, raids

Design notes: `docs/DESIGN-gear-raids.md`. `docs/GEAR.md` and `docs/MONSTERS.md` are written by `GearDocProvider` during `runDatagen`; do not edit them by hand.

- Stats: weapon engravings, armor options/engravings, set bonuses and level rewards all sum into `EngraveStat` through `GearStats.of(player)` (cached per tick, separate client/server caches). `JobWeapons.activeTotals` delegates to it. A new stat = an `EngraveStat` entry + the code that reads it. A stat that reads differently per class gets an entry in `EngraveStat.CLASS_WORDING` (EXTRA_SHOT: arrows/bullets/throwing weapons); show it with `stat.key(job)` (lang `<key>.<class>`) wherever a class is known — gear tooltips, engravings, talents, character/class screens, docs. Every source is added in `GearStats.collect` with its `GearStats.Source`, so `GearStats.breakdown` (character screen, I) lists the same lines; add new sources there.
- Armor (`job/gear/`): one content file per class (`ArmorContent` DSL, 10 sets x 4 pieces). Set/piece ids are saved item keys — never rename. Only the matching class/tier/level can wear a piece (`GearRules`); options roll lazily (`GearArmorItem.inventoryTick`) or on drop (`GearDrops.create`).
- Shop: one weapon + one armor piece per class and 10-level bracket (`GearIndex.shopItems`); everything else is drop-only. Evolution (blacksmith `CityNpc` -> `UpgradeMenu`) costs `GearUpgrades.etherCost` ether of the target bracket (3 at Lv 10 up to 50 at Lv 100) plus coins. The same bench rerolls armor options (`GearUpgrades.REROLL_CONDENSED` condensed essence + `rerollCost` coins, a quarter of the bracket price) into `ModDataComponents.GEAR_ROLLS_PENDING`; only `BUTTON_APPLY` copies it into `GEAR_ROLLS` (`BUTTON_KEEP` drops it), and stats never read the pending set.
- Named monsters: definitions in `NamedMobs.define()`, behavior in `NamedMob` (one method per `Ability.Type`). Models are body plans (`client/creature/NamedPlans`, `BossPlans`) rendered by `CreatureModel`; textures/glow/eggs are painted at datagen by `CreaturePainter` (`build/creature-preview.png` shows sizes in blocks — size hitboxes from it).
- Bosses (`entity/boss/`): `RaidBoss` holds phases, boss bar, damage divisor (health attribute is always 1000; toughness = `BossDef.health` x party scale; `RaidBoss.hurtServer` divides before `CombatHooks.modifyIncoming`, so anything there that replaces the amount — class arrows, skill arrows, summon hits — divides by `divisor()` again; until 0.5.10 those skipped it and a solo archer felled any boss in seconds), leash and the pattern scheduler. Each boss lists `pattern(id, phase, cooldown, range, busy, action)`. Every area attack is telegraphed first (`Telegraph` / `RaidBoss.circle|line|cone|donut|rain`), never shorter than `Telegraph.MIN_WARNING` (1 s) and drawn as wide as what it hits (a dash that hits around the body draws its strip 2 x that radius), and delayed code must check `alive()`. Monster fans with an even count get a middle shot (`MobProjectile.fanShots`). Raid boss damage is set so a player of the boss's level in that level's class set loses about 15% of their health to the biggest attack on Normal (`RaidBosses` javadoc); tune new bosses the same way. Nine bosses in level order, Lv 10-20 (Verdessa, the first raid) to 90-100 (Aethryx); each has its own `ArenaTheme`. Supplies scale with `RaidBosses.supplyTier` (by level, never by list position). New bosses: entity class + `BossDef` in level order + `ArenaTheme`/`Arenas` builder + `BossPlans` body plan (check `build/creature-preview.png` against the hitbox) + `RaidLang` phases/mechanics + a codex icon in `CodexScreen.raidIcon`.
- Class EXP (`JobEvents`, `JobProgression.levelExp`): kills pay the monster's base health (`JobEvents.baseHealth`, never what keystones or events add). Trial bosses (`Quests.BOSSES`) pay a share of a level at their trial tier's level (`JobEvents.TRIAL_BOSSES`, 0.5.8: Wither/dragon 0.5, Warden 0.3 because shriekers summon it again, elder guardian 0.25, mythril golem 0.2 at Lv 45; every `Quests.BOSSES` entry needs one, `JobClientGameTest` checks). Bosses drop 1 + base health / 150 condensed essence, the Warden a fixed `WARDEN_CONDENSED` (2, 0.5.11). Named monsters, lairs (`LairExp`: discovery, lord, chest, first clear), raids (`RaidDifficulty.exp`) and dungeons (`Dungeons.RUN_EXP`) pay shares of a level measured at min(player level, content level); dungeon run monsters and raid bosses pay no kill EXP; ores pay max(flat, share). Lairs are meant to be the main road to the level cap — keep new EXP sources on level shares. `GearDocProvider.growth` writes the table in docs/CONTENT.md.
- Raids (`raid/`): dimension type from `RaidDimension.bootstrapType` (datagen dynamic registry), level stem from `RaidDimensionProvider`. `Raids` runs instances (arena slots 1024 blocks apart, rebuilt by `Arenas.build` each time; raid arenas and dungeon runs start empty through `raid/InstanceSweep`: `clear` on open and close, and `ServerEntityEvents.ALLOW_LOAD` tags what spawns in a running instance and refuses what loads there from disk without the tag — a party that wiped left its chunks to unload and save everything, which loaded back into the next run in that slot); dying in the raid dimension never kills (`Raids.fall` -> sent home with items). Building and PvP are blocked there through `CityServices.blocksBuilding/blocksPvp`. Parties (`Parties`), raids and loot sessions (`raid/loot/`) live in server memory only.
- `GearRaidClientGameTest` checks content counts, armor/sets/cooldown floor, evolution, named spawns, runs every boss pattern once, the raid flow, dying in a raid and both loot modes; keep it passing.

## Endgame (`progress/`, `bounty/`, `enhance/`, `market/`, `talent/`)

Design notes: `docs/DESIGN-endgame.md`. `docs/ENDGAME.md` is written by `GearDocProvider` and the per-class talent tables in `docs/CLASSES.md` by `ClassDocProvider`; do not edit them by hand.

- Two reset clocks. Raids and guild bounties run on real time (`RealReset`, 0.5.5): a day starts at `RESET_HOUR` (6:00) in the server JVM's time zone, a raid cycle is 3 days; raid lockouts, raid modifiers and the three-day bounty renew per cycle, daily bounties per day. The latest day seen is saved per world (`real_reset` SavedData), so a clock turned back never resets twice; game tests jump ahead with `RealReset.skipDays`. Payloads send real time as 50 ms ticks and screens show it with `RealReset.remaining`. Everything else (lair rewards and lords, dungeon modifiers and free keystones, daily bread, world events, auction expiry) stays on the Minecraft calendar: `ResetCycle` (day = 24000 overworld clock ticks, cycle = 3 days), so lairs keep pace with play time. Bounty rewards and raid clear EXP were tripled when they moved to real time; keep that in mind before changing either clock.
- Lairs: goal chests and caches are `LairChestBlock` + `LairChestBlockEntity` with per-player, per-cycle contents (seeded by chest, player UUID and cycle; older cycles' rolls are dropped). The goal chest opens only for this cycle's victors: players within `CREDIT_RANGE` (32) of its lord when it died (`NamedMob.die` -> `lordDefeated`), plus the killer. A non-victor who comes within 20 blocks or tries to open it wakes a lord (`NamedMob.makeLord`) when none is up; a lord its chest no longer lists removes itself, and one dragged more than `LORD_LEASH` (24) blocks from its chest drops the chase and returns. The first open of a cycle counts as a lair clear (`Progress.lairCleared`).
- Raids: `RaidDifficulty` (unlock order, fee, health/damage, extra rewards), `RaidAffix` (2 per cycle, Heroic/Nightmare only), lockout keys `PlayerRecords.raidKey(boss, difficulty)` (locked members join as free practice), record table `RaidRecordsData`. The marshal screen gets cycle, modifiers and records in `OpenRaidPayload`. Gear lots are 1 + 2 per member (+ the difficulty's extra) so a party's share stays close to a solo run's; ether is graded at each member's level within the boss's range. Lair goal gear leans to the opener's class like other drops (`LairLoot.goal` gets the `JobData`).
- Kills are shared by damage (`progress/Contribution`): `LivingEntityMixin` records the health each player (or their tamed summon) really took off around `actuallyHurt`; support adds credit through `Contribution.healed/buffed/debuffed` (called from `Actions` heal/zone-heal, `allyBuff`, `debuff` — new support actions should call them too); at death `Contribution.shares` lists the hitters with ≥ `MIN_SHARE` (5%), best first. Class EXP is split by share with a group bonus, the top contributor (MVP) rolls gear/pet/gold-find/essence, named coins go to wallets by share, trial kill credit and pet growth go to every contributor. Use `Contribution.shares` (not `source.getEntity()`) for new kill rewards; on-kill procs stay with the killer.
- Codex, achievements and kill bounties count for each contributor and their party members within `Progress.SHARE_RANGE` (48) (`Progress.sharers`). The monster and item codex (`progress/Codex`) are records only: `ModAttachments.MONSTER_KILLS` (common monster kills by entity type id, from `Progress.afterDeath`) and `ITEMS_FOUND` (mod item paths, `Codex.scan` every second over inventory and carried bags); the client `CodexScreen` tabs read them, and `CodexSources` lists where items come from (shops, recipes, gear brackets, `screen.minecraft_mode.codex.source.<item>` lines in `CodexLang`). New mod monsters need a `Codex` place; new materials that only drop need a source line.
- Player data attachments (synced to the owner, kept on death): `RECORDS` (`PlayerRecords`: kills, clears, lockouts, achievements, title), `BOUNTY` (`BountyData` + merit), `TALENTS`. Everything that counts toward the codex, achievements and bounties goes through `Progress`; achievement and merit offer ids, bounty kinds and talent node ids (`class.branch.tier`) are saved keys — never rename them.
- Enhancement is the `ModDataComponents.ENHANCEMENT` component (level + artisan's spirit); `Enhancement.lines` feeds `GearStats`, `GearUpgrades.evolve` keeps it, names get "+N". Four +15 ✦5 armor pieces give 34% damage reduction on purpose (they filled the 50% cap alone): the rest has to come from sets, engravings, options and Ironskin. The bench is `EnhanceMenu` (Artisan Brokk). Protection takes a scroll, or `EnhanceMenu.PROTECTION_ETHER` Evolution Ether of the piece's bracket or higher. `Enhancement.glow` (from +10) drives the glint (`isFoil` on class weapons/armor) and the client `EnhanceVisuals` (slot frames via `ExtractItemDecorationsCallback`, particles for held weapons and full +10 sets, `/enhanceeffects`).
- Market: `AuctionHouse` (SavedData: listings + mailboxes) and `AuctionService` (rules, fees, expiry on overworld game time, search/filter/sort/paging). Every `AuctionActionPayload` carries the viewer's `Query` and the server answers with one page (`PAGE_SIZE` 8) in `AuctionStatePayload`; text search also sends the item ids whose names match in the client's language (the server only knows English names). Filled containers/bundles and stacks over `MAX_ITEM_BYTES` cannot be listed, so a page always fits in a packet.
- City NPC roles (plus `HUNT_MASTER`, see Town comforts): `BOUNTY_CLERK` (guild), `BROKER` (market stall with the lectern), `ENHANCER` (forge), `DUNGEON_WARDEN` (keep courtyard), `HERALD`, `GUIDE` (client `GuideScreen` topics in a scrolling pane; directions read `CityZone` incl. the `CityZone.Spot` shops and work places, a click opens the map there; the handbook button sends `GuideBookPayload` -> `CityServices.reissueGuideBook`, and `GUIDE_PAGES` must match the pages in `TrialLang`; topic texts without arguments write every % as %%, or the whole text shows raw — `ContentClientGameTest` checks), `QUARTERMASTER` (`city/StarterKit`, once per player via `ModAttachments.STARTER_KIT`; the shield joined later and has its own flag `STARTER_SHIELD`), `BAKER` (`city/DailyBread`, one stack per Minecraft day via `DAILY_BREAD`) and `CRIER` (notice board: `OpenNoticePayload` -> client `NoticeScreen` with resets, the next dusk event from `WorldEvents.ticksToNextEvent/nextEventIsInvasion`, the running titan or invasion, raid modifiers and records) on the plaza, and `STYLIST` in the jeweler's stall (`style/Looks` + `StylistMenu`: gear takes another piece's `item_model` and, for armor of the same slot, its `equippable`; `ModDataComponents.LOOK` names the look, the donor is used up, the price is half the bracket's weapon price, restoring is free); network actions check the NPC is within 8 blocks. `WAYMASTER` (travel, see Residence) is the newest. Append new roles at the end (the role is synced by ordinal).
- `EndgameClientGameTest` covers all of it (fake players for other sellers and loot rolls) and screenshots every new screen; keep it passing.
