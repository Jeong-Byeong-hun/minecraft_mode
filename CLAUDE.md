# minecraft_mode

Fabric mod for Minecraft Java **26.3**. Mod id `minecraft_mode`, package `com.minecraftmode`. See README.md for content.

## Toolchain

- JDK 25 required (`C:\Program Files\Eclipse Adoptium\jdk-25.0.4.101-hotspot`; the machine JAVA_HOME points at JDK 17, so set `JAVA_HOME` to it for Gradle).
- Loom plugin `net.fabricmc.fabric-loom` (non-remapping). 26.x is unobfuscated: **Mojang names, no mappings, `implementation` not `modImplementation`, `jar` not `remapJar`.**
- Fabric API uses Mojang-style names since 26.1 (`CreativeModeTabEvents`, `FabricBlockLootSubProvider`, `FabricTagsProvider.BlockTagsProvider`, `ModelLayerRegistry`, ...).
- Verify APIs against decompiled sources (`./gradlew genSources`) instead of guessing; many 1.21 names changed (e.g. `Identifier`, `EntityTypes`, `ContextIntProviders`, `Feature` replaces `ConfiguredFeature`, blocks have no codec).
- 26.x worldgen: statuses are merged (`TERRAIN` = noise + surface + carvers) and from then on chunks only keep the final heightmaps; `*_WG` heightmaps are stale/unprimed during decoration, and `ChunkAccess.getHeight` already returns the top block's Y (no `- 1`). Worldgen code that needs column heights should scan the column (see `CityGenerator.shapeTerrain`). Vanilla 26.3 races on the environment attribute tick cache (`ValueSampler.getDimensionValue` reads it twice while the server thread clears it), so a chunk-generation worker could get a null moon phase: `EnvironmentValueSamplerMixin` recomputes a null. Server-tick code must not load chunks with a blocking `getChunk` in a loop (a chunk whose generation throws never arrives): ask with a ticket and wait for `getChunkNow` (`HomesteadLand`).
- Client gametests run at render distance 5. For wide shots raise both `options.renderDistance()` and `PlayerList.setViewDistance`; chunk sending is still slow, so prefer fixed waits over `waitForChunksRender` there (`CityChecks` also writes a top-down `city_map.png`).
- 26.x client: GUI code uses `GuiGraphicsExtractor` (`extract*` methods instead of `render*`), screens open with `minecraft.gui.setScreen`, input is SDL (`InputConstants.KEY_*`, `Type.KEYBOARD`; no GLFW on the classpath). `Gui` makes a new `GuiGraphicsExtractor` every frame and Fabric's `ScreenEvents.afterExtract` runs after `extractDeferredElements`, so a tooltip set there never shows: set tooltips (and draw side panels that tooltips or the carried stack must cover) in `afterForeground` on container screens (`BuybackPanel`, `SellAllButtons`). Fabric's `PlayerBlockBreakEvents.AFTER` fires at `Block.destroy`, before `destroyBlock` takes the mined block's durability.

## Layout

- `src/main` — common code. `registry/` (blocks, items, effects, entities, tabs, tags, particles, menus, components, attachments), `entity/`, `economy/` (shop merchant, offers, wallet), `consumable/` (the 58 consumables and their buffs), `enchantment/` + `worldgen/` (bootstraps used by datagen; `worldgen/lair/` named lairs), `job/` (class system, `job/quest/` advancement trials, `job/gear/` class armor and stat totals), `loot/` (shop split, drops, ether, evolution), `entity/named/` + `entity/boss/` (named monsters, raid bosses), `raid/` (raid dimension, arenas, parties, instances, loot sessions), `city/` (the capital at 0, 0), `progress/` (reset cycle, records, achievements, titles, collection bonuses), `bounty/`, `enhance/`, `market/`, `talent/`, `companion/` (pets, mounts), `craft/` (professions, recipes, herbs, stations, crops, fish), `dungeon/` (dungeon dimension, runs, keystones), `event/` (world events, `MobPower` in `entity/`), `story/` (main story), `bag/` (bags, trash), `residence/` (residence dimension, land claims), `travel/` (the waymaster's destinations), `townquest/` (residents' quests), `jump/` (jump courses), `admin/` (the admin screen's server side), `network/`, `command/`, `mixin/`.
- `src/client` — renderer, model layer, **datagen providers** (`client/datagen`), `client/map` (minimap + world map: `MapData` explored colours per world/dimension saved under `<gamedir>/minecraft_mode/map` — keyed by the save folder plus a name hash in singleplayer, the address on servers (`MapClient.worldKey`; older display-name maps are copied over once), `TerrainScanner`, `MapTexture` GPU windows created lazily — never touch the GPU in static init, datagen runs the client entrypoint, `Waypoints` JSON (the server adds one with `MapMarkPayload`, e.g. the lair map's find, and the next big map opens there: `MapScreen.focus(x, z)`), `FieldBosses` (named monsters, mini-bosses and bosses the client sees, minus training dummies, plus the titan the server reports every second in `FieldBossPayload`; pinned to the minimap's edge when outside), `MapScreen`/`WaypointScreen`, keys M and comma).
- `client/hud` — `DurabilityHud` (the held item's "left / max" right of the hotbar once worn, `/durability false` hides it; worn items get the vanilla durability tooltip line without F3+H), `VitalsHud` (HP and MP bars over the left half of the hotbar in place of vanilla `HEALTH_BAR`/`ARMOR_BAR`, armor points beside MP; the class panel then drops its MP row; `/hpbar false` in `ClientSettings` brings the hearts back), `TooltipLayout` (wraps tooltip lines wider than half the screen, registered last, render thread only; tooltips taller than the screen start at the top and scroll with the wheel through `GuiGraphicsExtractorMixin`). Tooltip callbacks also run off the render thread with no player: the recipe book and creative search build every item's tooltip on a background thread, so they must never touch the font (it bakes glyphs into the GPU atlas) or client caches there (`JobTooltips.viewer()`); until 0.5.19 a Korean recipe book search crashed the game, `TargetHealthHud` (last hit monster's bar, top centre between the class panel and the minimap, under boss bars; the server names the target with `TargetHealthPayload` from `CombatHooks.afterDamage`), `TrashButton` (inventory "Bin" button -> `TrashPayload` -> `bag/Trash`, one undo), `BagTooltips`.
- `light/HeldLight` — a lit block item in either hand lights the player's surroundings with an invisible `minecraft:light` block the server moves along (air/water only, removed on move, logout, death, dimension change).
- Keybinds: R/X/V/Z skills, B innate, K class, I character (`client/job/CharacterScreen`), N talents, J codex, U pets, H mount, Y raid loot, M map, comma minimap, semicolon adventurer's menu (`client/menu`). G, P, L, O are vanilla defaults in 26.3 (quick actions, social, advancements, friends) — do not reuse them.
- `src/main/generated` — datagen output, committed. Never hand-edit; change the provider and run `./gradlew runDatagen`.
- `src/gametest` — client game tests, run in the order of `src/gametest/resources/fabric.mod.json`; keep them passing after changes. A test's name is its class name without `ClientGameTest`, lower case: `minecraftmode`, `enchantment`, `normalworld` (city + natural terrain), `job`, `gearraid`, `economy`, `lair`, `endgame`, `content`, `town`, `multiplayer` and `damage` (manual, never run unless named), `portraits` (manual: one picture per creature model). `./gradlew runClientGameTest -Ptests=job,town` runs only those (`TestSelection` makes the others return at once; never reorder or trim the list); `./gradlew runClientGameTestParallel` runs the whole suite in `-Pshards` (default 3) game clients side by side, balanced by `gameTestSeconds` in `build.gradle` (update it when a test's time changes a lot), about 8 minutes instead of 22 sequentially; it also takes `-Ptests`. Shard n plays in `build/run/clientGameTest<n>` (logs, screenshots). Every test ends its singleplayer block with `WorldClose.prepare(context, server)`: Fabric's client gametest API (6.0.8) races on `close()` — the deferred `Minecraft.disconnect` submits a blocking task to the server (`IntegratedServer.halt`) at the start of the tick phase, and a server that is behind schedule refuses fresh tasks (`MinecraftServer.shouldRun`) and parks on the phaser, so both threads wait forever (render thread in `executeBlocking`, server thread in `enterPhase`). Settle ticks do not fix it; `WorldClose` pushes the server's next tick deadline 2 s out so that tick has an idle window for the halt task. Keep it, and if a run still hangs after "Stopping singleplayer server as player logged out", take a thread dump (`jcmd <pid> Thread.print`) before killing it.
- Multiplayer test (manual, not in the suite): `MultiplayerClientGameTest` runs two scripted clients (`runMpAlice`, `runMpBob` in `build.gradle`, own game dirs, usernames Alice/Bob) against a real `runServer` (needs `run/eula.txt` agreed, `online-mode=false`, `white-list=false`, `enable-rcon=true`, `server-ip=127.0.0.1`). Start the server, then `./gradlew runMpAlice -PmpRcon=<rcon password>` and `./gradlew runMpBob` (both runs pick only `multiplayer`). Alice drives the server over RCON; the clients hand steps over with flag files in `build/mp`. Restore `server.properties` afterwards.
- `tools/TextureGen.java` (+ `tools/ClassArt.java`, `tools/QuestArt.java` for trial tokens and trainer/NPC skins — every `CityNpc.Role` needs one, `ContentClientGameTest` checks, `tools/EndgameArt.java` for endgame items and lair chests, `tools/ContentArt.java` for herbs, crystal, shard, keystone and station blocks, `tools/TierArt.java` for evolution shards/cores and imbue scrolls) — draws every texture except class weapons from scratch (no vanilla assets); run it instead of editing PNGs by hand. Class weapon textures are drawn at datagen time by `client/datagen/art` (`WeaponArtist`, `Shapes`, `Bows`) from each weapon's archetype, tier and `WeaponArt` colors; `runDatagen` also writes a review sheet to `build/weapon-preview.png`.

## Rules

- Content that is data-driven in 26.x (enchantments, ore features/placements, recipes, loot, tags, lang) goes through datagen, not hand-written JSON. Exception: `assets/minecraft_mode/equipment/mythril.json`.
- `ShopMerchant` is not an entity; `MerchantMenuMixin` must stay or shift-click trades crash the server.
- Gathering sells at flat prices (0.5.9): rare finds by how hard they are to mine (diamond 5S, netherite scrap 8S, mythril 12C), raw ores about 3/4 of their ingot, emeralds kept low (villagers hand them out). No shop may pay as much as any shop asks for the same item (`TownClientGameTest.checkShop`).
- Profession goods (0.5.12): `craft/CraftPrices` adds sell lines for every fixed-output recipe to its profession's shop (cooking -> grocer, alchemy + loose herbs -> alchemist, smithing -> blacksmith). Worth = raw materials (`ShopOffers.basePaid`, `CraftPrices.RAW` herbs/titan shard, `VANILLA` made vanilla items, made ingredients by their cheapest recipe) x `mastery(recipe level)`, cheapest recipe per item. Material worth never uses shop sale prices, so buying inputs from a shop and selling the product never pays. New recipes are bought automatically; new ingredients nobody buys count 0 until listed in `VANILLA`/`RAW`.
- Shop prices: base lists in `ShopOffers.trades(ShopType)`; market pressure lives in `MarketData` (world SavedData) and is applied through `MerchantOffer.setSpecialPriceDiff`. Keep `ShopType` ids and trade item ids stable — they are the saved market keys. Sales to shops are remembered by `MerchantResultSlotMixin` -> `economy/Buyback` (attachment `ModAttachments.SOLD`, last 10, exact stacks) and bought back at 1.5x through `BuybackPayload` (client `BuybackPanel` beside shop-titled merchant screens; the server checks the open menu is a `ShopMerchant` via `MerchantMenuAccessor`); buybacks never touch market pressure. `ShopType.fixedPrices` (the builder) skips pressure altogether. Sell-all (0.5.28): `economy/SellAll` through `SellAllPayload` (client `SellAllButtons` under the buyback panel) sells every whole trade of one sell line or of every line but essence, from the payment slots, main inventory (not the hotbar) and bags, plain items only, one `ShopMerchant.traded` per trade so pressure, wallet and `Buyback.recordAll` match single trades; the client preview estimates the pressure behind the current cost (`SellAll.estimate`).
- 26.3 reads natural spawns from the `NATURAL_MOB_SPAWNS` environment attribute; `NormalWorldClientGameTest` checks that Fabric `addSpawn` reaches it.
- Vanilla monsters never drop the weapons/armor they spawned with (`MobMixin` zeroes non-preserved drop chances for `minecraft:` types at death); what they picked up or were handed (preserved slots) still drops. Gear comes from the mod's own drops.
- No creepers: `ModEntities` removes them from every biome's spawn list and `NaturalSpawnerMixin` refuses any that still come (structure overrides, datapacks). Trials, lairs and bounties must not need them; gunpowder and flight-3 rockets are sold in the general store.
- Enchantments: each set is a class in `enchantment/` (`WeaponEnchantments`, `RangedEnchantments`, `ToolEnchantments`, `ArmorEnchantments`, `LifeEnchantments`) with `EnchantInfo` (key + en/ko name + en/ko description) and a bootstrap built on `EnchantmentFactory`. Prefer data-driven effects; marker enchantments are read in code by `ToolEnchantmentHandlers`, `craft/Crops` and `craft/Fishing` (hoes, rods), `CombatEnchantmentHandlers`, `ArmorAuras`, `BowItemMixin` and the client `LightmapRenderStateExtractorMixin`. Lang/tags iterate `ModEnchantments.ALL`. Vein Miner, Excavation and Timber break their extra blocks through `ToolEnchantmentHandlers.breakAll`, which stops while the tool still owes the mined block its use and keeps one more (`worn`), so area mining never breaks a tool.
- Auras must never stack: one fixed transient modifier id per aura (`aura/<name>`), level = max over nearby sources. Buffs use the enchantment's own attribute ids, so buff + aura stack by design.
- `docs/ENCHANTMENTS.md` is kept by hand from `src/main/generated` (en/ko lang + max levels; no datagen provider writes it): update it after changing enchantments.
- HUD panels on the left edge report their area with `BossBarLayout.reserveLeft` (`JobHud` starts each frame); `BossBarLayout` moves the vanilla boss bars right of them, or below when there is no room beside them, the minimap (`MinimapHud.box`) or the effect icons; `TargetHealthHud` goes under `BossBarLayout.bottom()`.
- After a change: `runDatagen` (if data changed) → `build` → the tests that cover it (`runClientGameTest -Ptests=...`) while iterating → the whole suite (`runClientGameTestParallel`) before committing, and look at the screenshots.

## Class system (`job/`)

- `JobClass` (7 classes x 4 tiers, titles + passives in en/ko; append new classes at the end — the network codec uses the ordinal), `JobData` (player attachment `ModAttachments.JOB`: class, tier, level, exp, MP, cooldowns; synced to the owner, kept on death), `JobProgression` (exp curve, tier levels 10/25/45/70; `advance` only checks level — items are the trial's job), `JobStats` (max MP/regen, attribute modifiers from level, passives and the held weapon's engravings), `JobEvents` (exp/essence from kills and ores, MP tick, death penalty, the talent migration on join).
- Weapon shapes (`Archetype`): append new ones at the end and give each a `Shapes` drawing, a model case in `ModModelProvider` if it is not handheld, and the shape-specific engravings it should get (`Engraving` `only` lists). 0.5.24 added one per class (greatshield, war fan, spellblade, chakram, blunderbuss, whip sword, needles) with a 2nd/3rd/4th-tier weapon each; new weapons take a level that is not the lowest of its bracket so `GearIndex.shopItems` (the guild's saved market keys) stays the same.
- Content: one file per class in `job/content/` built with the `ClassContent` DSL (`weapon(...)` + `skill(...)` + `Actions.*`). Startup validates tier/level ranges and skill counts (3 per weapon, 4 at tier 4); ids are saved item/cooldown keys — never rename them. Tooltips, lang and docs are generated from these definitions.
- Skills: `job/skill/Actions` holds every building block with its own tooltip template (`Actions.texts()` -> lang). Add new behavior there, not in content files. Damage from skills/shots goes through `CombatHooks.deal` with a `DamageKind`; `LivingEntityMixin` feeds `CombatHooks.modifyIncoming` (passives, engravings, marks, stances, vulnerability). Delayed steps use `SkillScheduler`; `SkillContext.valid()` must be checked in delayed code. Every `barrage` projectile flies at the crosshair, so one target takes count × mult: keep that close to the tier's other skills (0.3.4 retuned the outliers). Skill summons carry their caster (`Actions.summoner`): raid bosses take their damage and `Contribution` credits the caster.
- Crits, areas, summons (0.4.0): `CombatHooks.outgoing` rolls crits for basic hits, shots and `DamageKind.SKILL` (CRIT_REFUND stays basic-only); skill summons (`Actions.markSummon` tags the caster and power) hit for power x `Actions.Summon.share` through `CombatHooks.modifyIncoming` like skills. Area hits go through `SkillContext.hitArea` (each target gets `areaShare`: full up to `AREA_FULL` = 5, then sqrt(5/n)) and their factories apply `SkillContext.AREA_SCALE` (0.85) to the listed multiplier, shown in tooltips. New area actions must do both. Every damaging action reports `SkillAction.estimate(targets)` (attack/move overloads, `estimated`), which `ClassDocProvider` turns into the 1/5-target columns and the "스킬 피해 비교" section. `ProjectileAction`: even fans get a middle shot (`shots`, `each`), `parallel(width)` sends shots side by side, non-arcing shots aim at the cast target (aim assist), and the homing shots of one fan split the enemies between them (`SkillProjectile.Volley`, the middle shot keeps the crosshair enemy), so a lone target takes one shot as `estimate` counts. `Actions.lifesteal` only heals off the skill's own hits; a buff skill without hits uses `lifestealFor` (timed, `CombatState.lifesteal`, every hit). Percent and flat cooldown cuts together stop at `SkillCaster.MAX_COOLDOWN_CUT` (60%). `CombatHooks.showHit` sends `TargetHealthPayload` + `DamageNumberPayload` (client `hud/DamageNumbers`, `/damagenumbers` in `ClientSettings`). Training dummies (`entity/TrainingDummy`, armor-stand bodies that are `Enemy`, the boss kind `EliteMob`) never take damage, never move except falling (`setDeltaMovement`) and cannot be dressed or stripped (`interact`), call `modifyIncoming` and the AFTER_DAMAGE event themselves and report to `city/DummyMeter`; `CityServices.keepDummies` keeps `CityZone.dummies` in the warrior arena: a post keeps the dummy on it, an empty post takes the nearest stray of its kind in `CityZone.dummyArea` (new one only when none), strays go back once not hit for `DUMMY_RETURN_TICKS` (`TrainingDummy.hitWithin`), extras are removed (until 0.5.16 a moved dummy got a twin and they piled up).
- A class weapon is "active" only when class, tier and level all match (`JobWeapons.isActive`); otherwise it is a plain weapon (basic attack/shot only, no skills, no engravings).
- Aiming and hits: `SkillContext.lookPoint` stops only at blocks (beams pass through monsters); skills placed where the caster aims use `groundPoint`/`aimPoint`/`SkillContext.aimed`, which stop at the first enemy in the crosshair. `SkillContext` keeps the view and that enemy from the moment the skill started (`aimedEnemy`), so delayed and repeated area steps land where the caster aimed, following that enemy; `barrage` lobs projectiles with gravity onto the target (`Actions.lob`). `SkillProjectile` sweeps its next move (`SkillProjectile.reach`, radius `ProjectileStyle.hitRadius`: sword waves 0.75, the rest 0.3) before vanilla's check, because vanilla never hits a hitbox the projectile starts inside (a monster pressed against the caster) and has no margin for the first ticks; `AbstractArrowMixin` adds the same reach to class arrows (`CombatHooks.classArrow`), and `CombatHooks.modifyIncoming` lets them through the damage cooldown like every other shot. The extra projectiles of a basic shot (`EXTRA_SHOT`, cap 4) hit each enemy once (`BasicAttacks.Fan`, shared by the shot's class arrows through `AbstractArrowMixin.canHitEntity` and by its `SkillProjectile`s, blasts included), so a lone target takes one as `ClassComparison` counts; 0.5.10 stopped whole fans landing on raid bosses. Instead each extra projectile adds `BasicAttacks.EXTRA_SHOT_DAMAGE` (4%) basic shot damage in `shotBonus`, a steady 1-target worth whatever the target's size. `rain` drops each projectile on a random enemy inside its circle (led by its walk) and starts it under any roof (`Actions.sky`), so its multipliers are per projectile on one target. Portals and blades launched beside the caster start at `SkillContext.openPoint` (never inside walls or low ceilings). Class projectiles (`CombatHooks.classProjectile`) ignore vanilla's projectile immunities (`EndermanMixin`, `WitherBossMixin`, `ShulkerMixin`, `DragonSittingPhaseMixin`, `ProjectileDeflectionMixin` for breezes); `SkillProjectile` damages the Ender Dragon through its parts.

## Trials and trainers (`job/quest/`, `entity/ClassTrainer`)

- Choosing a class and every advancement goes through that class's `ClassTrainer` (no advance button). `Quests` defines the 28 trials (`<class>_<tier>`) and their 28 trial tokens. Tier 1 is `QuestDef.instant()` (no goals, tokens or materials): accepting it at level 10 advances on the spot, and its token no longer drops but stays registered. Tiers 2-4 are real trials = kill goals + token count + materials (always essence; tier 3/4 also need a golem/boss kill). Quest and token ids are saved keys — never rename them.
- `QuestData` (attachment `ModAttachments.QUEST`, synced to the owner, kept on death): active trial id, kill progress, `visitedCity`. `QuestService` holds the rules (status per trainer, accept/complete/abandon, kill credit on `AFTER_DEATH`); screens read the same synced data. Tokens only drop for a player whose trial needs them and go straight into the inventory; bosses (`Quests.BOSSES`) credit everyone with the trial within 64 blocks.
- One-time quests pay EXP and merit (0.5.47): a finished trial `QuestService.TRIAL_EXP`/`TRIAL_MERIT` by tier (`pay`, instant tier 1 too), a story chapter `Story.CHAPTER_EXP` and `Story.merit` (Act I/II) on top of its coins and items, one-time town quests by their tier like dailies.
- Trainer actions come in as `QuestActionPayload` and need the trainer within 8 blocks; right-clicking a trainer sends `OpenTrainerPayload` (client `TrainerScreen`).
- Trial lang (trainer names/greetings, trial texts, tokens, guide book) lives in `client/datagen/TrialLang`; `ClassDocProvider` writes the trial table into `docs/CLASSES.md`.

## The capital (`city/`)

- Stormhold is generated at 0, 0 in the overworld of noise worlds only (flat test worlds have none). `ChunkGeneratorMixin` calls `CityGenerator` during decoration: chunks inside `CityZone.CORE` are flattened to `CityZone.baseY` (median natural height, cached per seed) and built; vanilla features/structures there are suppressed except ores; a `BLEND` ring eases terrain back. Every write goes through `Build`, which clips to the chunk being decorated — buildings must be pure functions of coordinates (no randomness that differs per chunk, no reading neighbour chunks).
- Districts: `CityCore` (roads, plaza + fountain, walls, gates, lamps), `CityNorth` (keep + raid gate, mage tower, Enchanter's Hall, warrior arena, Hunter Association), `CityMiddle` (old town + rogue Shadow Hall, cathedral, homes), `CitySouth` (archer park + Urahara Shop, market + alchemist + Adventurers' Guild with shops/engraving tables, forge, harbor + pirate ship). Trainer posts are `CityZone.trainerHome`; `CityServices.keepTrainers` (every 100 ticks) spawns missing trainers, removes duplicates and brings wanderers back. The hall's four enchanting tables (15 bookshelves each, level 30), the grindstone in the opening of each table's ring (`CityZone.grindstones`, never between table and shelves; `CityServices.keepGrindstones` adds them to older cities) and the city anvils are listed in `CityZone.enchantingTables/anvils`; `CityServices.keepAnvils` replaces worn anvils because nobody can place blocks in the city.
- Training Grounds (`city/TrainingGrounds`): a sealed hall at dy -18..-9 under the south-east park, built by the generator like the districts (stairs from a pavilion at x 22..24, z 12..17). While a classless player is inside, monsters tagged `TrainingGrounds.TAG` step out of the alcoves (cap grows with trainees), classless killers get double class EXP (`JobEvents`), the guards skip them only inside the hall, and they are removed when nobody trains.
- Multiplayer-first: world spawn is the plaza (respawn radius 0); first join teleports there and gives the guide book. Inside the walls (`CityZone.inside`) the city is a safe zone: no hostile natural spawns (`NaturalSpawnerMixin`), city guards (`CityServices.driveOffHostiles`, every second) remove hostile mobs that get in anyway (climbing spiders, cave wanderers, eggs; skill summons and NoAI mobs are exempt), no building/breaking for non-op survival players (`PlayerMixin`, `BlockItemMixin`), no PvP (`CombatHooks`), no explosion block damage (`ServerExplosionMixin`), and food/saturation stay full (`CityServices.feedResidents`, every tick).
- Outskirts (`CityZone.outskirts`, up to `OUTSKIRTS` = 196 from the centre): no hostile natural spawns on the surface (top block - `OUTSKIRTS_SURFACE_DEPTH`), as if lit; caves below and animals still spawn (`CityServices.blocksSpawn`).

The client learns whether the overworld has the capital from `CityInfoPayload` (sent on join); the map draws Stormhold, every NPC/trainer post and the Training Grounds stairs from `client/map/CityPlaces` (big map: NPC tab, hover names, `MapScreen.focus`).

Inside a raid, dungeon or jump course the pause menu also offers "return home" (`MenuActionPayload.LEAVE` -> `JumpForest.leave`/`Raids.leave`/`Dungeons.leave`). - `AdminScreen` (operators only; button in the adventurer's menu): players (class/tier, level, EXP, MP, cooldowns, heal, trials, money, story chapter, go to/bring, game mode, kick), travel (coordinates per dimension with "surface" Y, `Destination` places, the capital's `CityPlaces`, gather everyone, summoning up to `Admin.MAX_SUMMON` of any summonable type at the target's feet or crosshair, tagged `Admin.KEEP_TAG` so city guards leave them), content (dungeon/raid start for the target's party, `Raids.stop`/`Dungeons.stop`, titan/invasion/stop), server (time and weather run fixed vanilla commands, `RealReset.skipDays`, broadcast) and economy (market listings -> `AuctionService.adminCancel` to the seller's mailbox; land claims -> `LandOffice.release`, items and the deed to the owner or, offline, their market mailbox). Actions apply to the picked player ("" = the operator).
- Every `AdminActionPayload` goes through `Admin.handle`: `Admin.allowed` (`COMMANDS_GAMEMASTER`) first — the client hiding the button is cosmetic — then range checks, a `[Admin]` log line, the same code the operator commands use (`JobCommand`/`EventCommands`/`WalletCommand` helpers), and a fresh `AdminStatePayload` from `AdminState` (market and land one page at a time, the page and market search remembered per operator). New admin actions: a constant in `AdminActionPayload`, a case in `Admin.act` that validates its arguments, a control in `AdminScreen`, lang in `MenuLang`.
- `MenuScreenBase` is the shared frame: tabs, labels laid out with the widgets, text boxes whose text survives `rebuildWidgets` (26.3 `EditBox` has no input filter, so `box` puts a refused edit back), two-click `confirm` buttons. `TownClientGameTest` runs `MenuChecks` (party, pay and dice through the menu, refused non-operator, admin money/level/class/summon/teleport/market/land, screenshots of every tab) before its bed-respawn check, because `TestServerConnection.getServerPlayer` keeps the pre-respawn entity after it.

## Characters (`character/`)

- Character select: `CharacterRoster` (server SavedData, field names are save data) keeps per account the slot being played, the slots owned (`Characters.BASE_SLOTS` 3, never fewer when read, bought for `SLOT_MERIT` merit up to `MAX_SLOTS` 7) and the other characters as saved player data (`saveWithoutId`). The played character stays in the vanilla playerdata. `Characters.switchTo` saves the player, clears every `ModAttachments.all()` attachment, effects and inventory, `load`s the other slot onto the same `ServerPlayer` and sends everything again (`resync`: attachments re-set so Fabric syncs them, game mode, inventory, effects, `JobStats.refresh`), then teleports to the saved dimension (the world spawn when that dimension is gone); `Titles.apply` refreshes the tab-list title; an empty slot starts fresh at the world spawn through `CityServices.welcome`. Shared by the account: ender chest, codex and wallet (`Characters.SHARED`; wallets of characters stored before 0.5.24 are poured in on their first load), recipe book, land claims and the market (UUID keyed), and merit and the land deed count (0.5.46: the two `BountyData` fields ride on the live character, `takeStoredMerit` strips them from stored characters and pours older stored values in on their first load, `keepMerit` carries them over a load or a fresh start; the bounties themselves stay per character). Only inside the capital's walls (`CityZone.protectedAt`), so nobody slips out of a fight, and never while rewards are still owed to the account (`Raids.committed` — fallen raiders wait in the keep; members who left and practice members are free —, a `LootSessions` seat, `WorldEvents.committed`; until 0.5.24 a fallen raider handed the clear to another character). After a switch that player's file (`PlayerListInvoker`, not every player's) and the roster are saved together and the new character's pet comes back (`Companions.restore`). The roster changes only after the load worked; a failed load puts the saved current character back. New attachments are per character unless added to `SHARED`.
- Joining with another character stored (a new account's empty slots do not count; a player still in the lobby chooses again) (outside raids and dungeons, which handle their own returns) sends the player to the lobby (`character/Lobby`: `minecraft_mode:lobby`, a void on the overworld dimension type, stem by `RaidDimensionProvider`, one room built at 0, 0) and puts them in `Characters.choosing` (server memory) until they `enter` a slot: no damage, no using/hitting/breaking, only character menu actions, and the town rule does not apply. Where they came from is `CharacterRoster.Account.origin` (saved, so logging out while choosing still returns them there; a character saved from the lobby is saved at its origin). A vehicle the player rode stays behind (`Origin.vehicle`) and `Lobby.tick` puts them back on when they return. Pets do not follow into the lobby, the minimap does not record it, and `ServerGamePacketListenerImplMixin` drops a choosing player's commands. `Characters.onJoin` is the join handler (game tests call it to stand in for a reconnect). `CharacterListPayload.prompt` carries the choosing state; the client keeps `client/menu/CharacterSelectScreen` open while it is true (Esc does nothing, Done = continue). Its cards draw each character as a `RemotePlayer` with the account's profile in the gear the server sends (`Characters.GEAR_SLOTS`, kept with each stored character); the figures need an entity id (`FIGURE_ID`) for the held-item renderer.
- UI: the adventurer's menu "Characters" tab (`MenuActionPayload.CHARACTERS/CHARACTER_SWITCH/CHARACTER_BUY/CHARACTER_ENTER`, `CharacterListPayload`); the tab lists the slots, the select screen shows them as cards.

## Residence (`residence/`)

- `ResidenceDimension`: `minecraft_mode:residence`, a flat plains stem on the vanilla `minecraft:overworld` dimension type (no own `DimensionType`; stem written by `RaidDimensionProvider`, grass at `SURFACE_Y`, `structure_overrides: []`). No hostile spawns (`CityServices.blocksSpawn`). `ResidenceTown` (called from `ChunkGeneratorMixin` at decoration, clipped per chunk like the capital) builds Stormhold's style there: the square (chunks within `SPAWN_CHUNKS` of 0, 0) is `CityCore.plaza` drawn through `Build.shifted` plus four corner towers, and four avenues paved like the capital's roads along chunk column/row 0 out to the world edge; both are public (`ResidenceDimension.isPublic`): no claims, no building. Plots between the avenues stay free-form. Either side of the square's waymaster stand the farmer and fishmonger shop blocks (`ShopType.FARMER/FISHMONGER`, the grocer's crop and fish lines under the grocer's market pressure, `ShopType.marketId`; `ResidenceDimension.shops`, put back in older residences by `keepShops`); `ResidenceRules` lets anyone right-click a `ShopBlock`.
- Getting there: the waymaster (`CityNpc.Role.WAYMASTER`, Waymaster Orin) west of the fountain, and a second one at the residence square (`ResidenceDimension.waymaster`, kept by `ResidenceRules` through `CityServices.keepNpc`). `travel/Travel` + `travel/Destination` is the general travel NPC: a right-click sends `OpenTravelPayload` with the places offered where the player stands (`Destination.offeredIn`), the client `TravelScreen` answers with `TravelPayload` (NPC within 8 blocks). New places = a new `Destination` (append: the ordinal is synced) with its `offeredIn` and `spot`.
- `LandClaims` (server SavedData): a claim is the deed user's whole chunk column (0.5.46: `Claim.contains` ignores y; `minY`, under the feet, only marks the floor the borders and the land screen show). One owner and one claim per column, `MAX_CLAIMS` per owner, none within `SPAWN_CHUNKS` of the square. Trust lists are per owner (all their land). `Claim` fields and the saved shape are save data — keep them stable. Saves from before 0.5.46 held 16x16x16 boxes stacked per column: loading keeps the first claim of a column and owes its owner the rest as deeds (`refunds`, saved), which `ResidenceRules` hands back on join (`takeRefunds`, also lowering the account's deed count). `LandRestore` resets the whole column (section by section, skipping air sections above the flat land).
- `ResidenceRules`: inside a claim only owner + trusted may break/place/use blocks (any right-click, not just block-changing items) or touch non-monster, non-player entities; unclaimed residence land is not buildable at all; ops/creative are exempt (`CityServices.exempt`). Break/place go through `CityServices.blocksBuilding`; explosions break nothing there (`ServerExplosionMixin`). Crossing into other land shows the owner on the action bar (`label`), refusals say whose land it is.
- Border lines: `LandClaims.version` bumps on every claim/trust change; the HUD tick sends `LandBordersPayload` (every claim + its relation to the viewer) to residence players whose synced version is stale (so also on entering). Client `LandBorders` emits vanilla gizmos (`Gizmos.cuboid`, depth-tested) in `END_CLIENT_TICK` for claims within `RANGE`, plus an outline on top of the floor block so the edge shows on the ground.
- No PvP anywhere in the residence (`CityServices.blocksPvp`).
- Crops grow while nobody is near (`IdleGrowth`; it catches up at the end of the tick from a copy of the waking set and only once the 3x3 chunks around are loaded — catching up reads neighbours, and a neighbour finishing its load fires the status event again): a residence chunk with crops that stops block-ticking saves the game time (SavedData `idle_growth`), and when it ticks again its crops get the random ticks they missed through their own `randomTick` (light, farmland and slower mod crops still count; crops too dark to grow are skipped). Chunks still ticking at a server stop are paused in `SERVER_STOPPING`, and a pause is never moved later (a chunk that woke but has not caught up yet keeps its first one). `ResidenceChecks.checkIdleGrowth` covers it.
- Nothing crosses a claim edge (`ResidenceRules.crosses`: different owner, unclaimed counts as one): fluids (`FlowingFluidMixin`), pistons (`PistonStructureResolverMixin`: head, pushed blocks and their targets, broken blocks), dispensers/droppers/crafters facing out (`DispenserBlockMixin`, `CrafterBlockMixin`), hoppers pushing out (`HopperBlockEntityMixin` on `ejectItems`, before Fabric's transfer API), fire spread/burn and lava ignition (`FireBlockMixin`, `LavaFluidMixin`). Player-caused damage (arrows, TNT) to protected entities is refused (`ResidenceRules.blocksDamage`: `ALLOW_DAMAGE` for living ones, `BlockAttachedEntityMixin` for frames, paintings, boats, minecarts).
- `LandDeedItem` (merit shop only, offer `land_deed`: `Bounties.DEED_MERIT` for the first `FIXED_DEEDS` (2), then `DEED_RAISE` more per deed past them, counted in `BountyData.deeds` — abandoning refunds the item, not the count; merit and the deed count belong to the account, see Characters): use = claim, sneak-use or `/land` = `LandScreen` (client) via `OpenLandPayload`; `LandActionPayload` trusts online players by name, untrusts, abandons (`LandRestore`: the column goes back to `ResidenceDimension.natural` layers, entities in it are removed, container/frame/armor-stand items and the deed go to the owner). `ResidenceChecks` (run from `TownClientGameTest`) covers it.

## Economy, consumables and raids

- Coins never sit in the inventory: `Wallet` (attachment `ModAttachments.WALLET`, copper) deposits them every 10 ticks; `Coins.total/take/give` see wallet + inventory. Shops pay from the wallet through `MerchantMenuMixin` (fills the payment slots). `KEEP_INVENTORY` is forced on at server start.
- Bound items (`ModDataComponents.BOUND`: starter kit, starter bags, advancement kits; evolution keeps it) never sell: `ItemCostMixin` makes every trade cost refuse them, `AuctionService.sellable` keeps them off the market. They can still be worn, used and moved (ender chest).
- Essence is one currency (`economy/Essence`, condensed = 9): every essence cost (shops via `MerchantMenuMixin`, trials, profession recipes, engraving, enhancement) takes either kind and gives change as loose essence — check with `Essence.held`, pay with `Essence.take`. Profession recipes that make essence stay exact (no condense-for-change loop). Using essence condenses 9 → 1, using condensed essence breaks it (`item/EssenceItem`).
- Coin sinks scale with `GearShop.bracketPrice` (raid fee, engraving/reroll/removal, evolution, armor reroll), so they grow with level. Keep new sinks on that curve; coin sources too (gold-find procs pay `JobEvents.goldFindCopper`).
- `consumable/Consumables` defines the 58 consumables (`ConsumableDef`; the last 18 are cooking-only dishes of the mod's crops and fish, tiers 1-5; lasting effects are 10 minutes = `Consumables.LONG`); buffs are marker effects whose stats `BuffEffects` feeds into `GearStats`. Icons are drawn by `client/datagen/art/ConsumableArtist`. Item ids are saved keys. `docs/CONSUMABLES.md` is generated.
- Raid bosses declare their mechanics in `RaidBoss.mechanics()` (first at an HP fraction, then on an interval, never closer than `MECHANIC_GAP` = 45 s). Mechanic damage uses `RaidDamage` (bypasses armor and resistance, not totems or feather). Team mechanics must scale their requirement with party size so solo players can clear them.
- Soul Reaper and Hunter passives, and the damage parts of Mage's, Rogue's and Pirate's (0.5.1–0.5.3) and Warrior's (0.5.47), are stat lines in `job/gear/ClassPassives` (added up by `GearStats`); the rest of the first five classes' passives stay rules in `CombatHooks`/`JobStats`/`SkillCaster`/`BasicAttacks`. A mage's basic shots (orbs) also get the mage's skill damage (`BasicAttacks.shotBonus`).

## Named lairs (`worldgen/lair/`)

- `NamedLairs` defines one lair per named monster (`LairDef`: setting, landmark shape, palette, biomes, `LairMobs` spawn list, decor). All 22 share one structure set (`minecraft_mode:named_lairs`, one lair per cell, excluded near villages, the capital and the End's main island). Structures and the set are datagen (`bootstrapStructures/bootstrapSets`).
- Lair layouts (0.5.48, `worldgen/lair/LairLayout`): each `LairPiece` saves the geometry it was started in ("Layout"; none = `V1`: 3-wide, 4-high corridors, `CELL` 4, roof 5, the steep one-block shaft spiral) and builds every chunk in it, because a lair half generated before an update must meet its other half; new lairs are `CURRENT` = `V2` (4-wide, 6-high corridors, cell 5, roof 7; the shaft spiral has a flat landing at every corner so each stair is met from its low front, `gentleStep`; a second tower door towards the lair; ziggurat stairs 5 wide). Everything that measures a lair goes through the piece's layout (`goalPos`, `entrance`, `shaftZ`, `topOffset`, `Maze.wall(lx, lz, cell)`); `LairDef.size()` and the static helpers without a layout mean `CURRENT` (new lairs, docs). `LairLayoutChecks` (lair test) builds both side by side and checks them.
- `LairPiece` builds everything in `postProcess` clipped to the chunk; the maze (`Maze`) and goal are pure functions of the piece's seed. The piece box includes `GROUNDS` blocks of land around the lair; the structure's MONSTER spawn override applies there, and `NamedMob.checkSpawnRules` relaxes height band and spacing inside its own lair (`NamedLairs.at`).
- Loot is `LairLoot` (coins always + at least one reward, gear share `GEAR_SHARE`). `/place structure` does not register structure references, so `NamedLairs.at` only sees naturally generated lairs (`NormalWorldClientGameTest` locates one); `LairClientGameTest` builds every shape with `/place`.
- Lair map loop (0.5.36, `worldgen/lair/LairTravel`, like PoE maps): reading a lair map finds the nearest lair in the player's dimension whose named range comes within `LEVEL_REACH` (5) of their class level (`Target.fits`; readers below `NamedLairs.lowestLevel` count as it; 0.5.46 dropped the fallback to the nearest lair of any level and searches up to `RINGS` 8 instead, refusing when none fits), skipping lairs cleared this cycle (`ModAttachments.LAIR_CLEARED` = `LairTravel.Cleared`, keys `dimension|goal chest pos`, per account), marks the waypoint and sends `LairOfferPayload` -> client `client/lair/LairTravelScreen`. Travel (`LairTravelPayload.TRAVEL`) re-checks, waits for the gate's 3x3 chunks with its own loading ticket (never a blocking `getChunk`), uses up the map on arrival and teleports to `LairTravel.safeSpot` by `LairPiece.entrance()`. Refused in raid/dungeon/lobby/residence dimensions and while choosing. The first goal-chest open of a cycle calls `LairTravel.cleared`: the next map via `Bags.give`, and `LairClearPayload` when the chest knows its exit (the client shows `LairClearScreen` once no screen is open); `LairTravelPayload.EXIT` works only within `def.size() + GROUNDS` of the chest, once per clear. Goal chests save their gate spot ("Exit", set by `LairPiece.goal`); older chests look it up from the structure start (natural lairs only). Exit offers and trips live in server memory.
- Room for big monsters (0.5.46, `entity/SpaceCheck`; only suffocating blocks count, so a lord brushing its chest is not stuck): old lairs' corridors are four high (new ones six since 0.5.48), so a lord only grows (`LORD_SCALE`) as far as its spot allows (`growTo`, checked in `tickLord`), lords and champions dragged off go home to the nearest free spot (`goHome` -> `nearestFree`), `Attacks.summon` places minions only where they fit, and a named monster, minion or anything on lair grounds that takes `IN_WALL` damage is moved to a free spot instead (`LairClientGameTest.checkRoom`). Until then big lords suffocated in the roof.
- Tier lairs (0.5.49, `worldgen/lair/LairTier` numbers, `TierLairs` runtime): a Lv 100 character's lair clear gives a tier 1 map (`ModDataComponents.LAIR_TIER`, same `LAIR_MAP` item; untiered maps keep the world loop). Reading one (`LairMapItem.use` -> `TierLairs.offer` -> client `TierLairScreen` -> `LairTravelPayload.TIER` -> `confirm`) builds a random lair's `LairPiece` in a slot of the dungeon dimension (x `ORIGIN_X` 8192, z = slot x `SPACING` 256; loading ticket, built once `getChunkNow` sees every chunk, one per tick; surface lairs on a fenced plate so the foundation does not run 40 blocks into the void), removes its lair chests, fills cells with packs (`LairMobs.pick`, dungeon power 100 x tier), `ELITES` named monsters and a champion lord at the goal (`NamedMob.empower`: typical Lv 100 power x tier, never saved). The lord's kill pays the active members (`reward`: Lv 100 treasure x `rewardScale`, next maps `nextMaps`, shards/cores, imbue scrolls); `LIVES` falls wake at the gate. Hooks in `Dungeons` (shared dimension): `ENTITY_LOAD` stray cleanup and `ALLOW_LOAD` sweep tags ask `TierLairs.insideAny/tagAt`, `fall`, `leave` and `onJoin` (`rejoin`) go to `TierLairs` first. Runs are server memory: `SERVER_STOPPING` and an all-offline party mail the map back. `MapCombinerMenu` (`CityNpc.Role.MAP_COMBINER`, by the guild's cartography table) raises maps (`combineChance`, condensed essence / Lv 100 ether) or merges three. `LairClientGameTest` runs `TierLairChecks`.
- Pet evolution (0.5.49): `Companions.Data.evolutions` (optional codec field, id -> stars 1..3), `evolve` (shards/cores from inventory and bags), `evolvedLines` x `evolveScale` (2.1/2.7/3.75); `PetEntity.applyEvolution` scales the pet. Imbue scrolls: `enhance/Imbue` (component `IMBUE`: slot + grade, numbers in `ImbueSlot`), `ImbueScrollItem` x 18, applied by `EnhanceMenu.BUTTON_IMBUE`; `GearStats.Source.IMBUE`, carried by `GearUpgrades.evolve` and `Accessories.inherit`.
- Lords follow the strongest player near: woken raised to the highest class level within `CREDIT_RANGE` (`NamedMob.raiseTo`: MobPower toughness/damage toward `NamedMobs.typicalPower(level)`, never saved; the chest keeps "LordPower" and re-applies it after a reload), and refitted every 40 ticks out of combat (`REFIT_CALM` 100 ticks, `NamedMob.hurtWithin`) by `LairChestBlockEntity.refit`/`NamedMob.fitPower` — up, or back to its own level when nobody strong is near, healing on change; an unbeaten lord of an earlier cycle leaves. `MobPower.clearDamage` drops only the damage multiplier.
- Lair rewards follow the level actually fought, capped by the player's: the chest keeps uuid -> level each victor beat this cycle's lord at ("VictorLevels"; `beatenLevel`), `contentLevel` = max(lair top level, beaten level), `gradeLevel` = min(player level, contentLevel). Goal-chest loot is graded at `gradeLevel` through `LairLoot.range` (the player's bracket, lo = max(def.lo, min(bracket, 90)), hi = lo + 10, or the lair's range); caches link to their goal chest ("Goal", set by `LairPiece`) and grade the same way (older caches use the lair's range); raised lords drop at min(top contributor's level, raised level). Lair EXP (0.5.36): lord kill `levelExp(player, lord.effectiveLevel(), LairExp.LORD)`, chest and first clear at `contentLevel`, discovery at the lair's top level; shares DISCOVER 0.6, CHEST 0.6, FIRST_CLEAR 2.0, CACHE 0.1, LORD 1.0 (shared by contribution). `JobEvents.LORD_SHARE` (0.5) only covers titans, warlords and dungeon champions. `LairTravel` skips targets and spots outside the world border, clears its state on `SERVER_STOPPED`, drops a trip and its ticket on disconnect, and a failed way back says `exit_failed`. Lair maps have a 40-tick use cooldown (`LairMapItem.USE_COOLDOWN`: the search may generate structure starts), and `LAIR_CLEARED` is in `Characters.SHARED` (chests remember the account). `LairClientGameTest.checkLoop` and `NormalWorldClientGameTest.checkLairMap` cover the loop (their `setLanguage` waits for `gui.overlay() == null`, or KO screenshots show the loading screen).

## Later content (`companion/`, `craft/`, `dungeon/`, `event/`, `story/`)

Player-facing summary and numbers: `docs/CONTENT.md` (written by `GearDocProvider` during `runDatagen`; do not edit by hand). `ContentClientGameTest` covers all of it; keep it passing.

- Titles: `Titles` keeps the worn title in the synced `ModAttachments.TITLE` attachment and `PlayerNameMixin`/`ServerPlayerTabNameMixin` prefix the display and tab names. Never use scoreboard teams for this (other plugins/datapacks own them).
- Paragon (`job/Paragon`): experience past level 100 goes into paragon levels; stat ids are saved keys. Stats stop at `MAX_RANK` (50) except the endless ones (`Stat.endless`: Might, Vitality), whose ranks past it count `PAST_MAX_SHARE` (half) through `Stat.worth`, because keystones have no top level. 0.5.17 raised the ranks 2-3x (fifty ranks used to be one armor option line). Awakening (`Enhancement.awaken`, ✦1–5) is a third field of the enhancement component; it never fails.
- Professions (`craft/`): `Profession` (exp in `ModAttachments.PROFESSIONS`; ids are saved keys, append only; `Profession.CRAFTING` are the three with stations and recipes, farming and fishing level in the field and show their gains on the action bar), `CraftRecipes` (code, not JSON; outputs may depend on the crafter; at most `MAX_INGREDIENTS` = 4, all the station row shows), `CraftMenu` (button id = recipe index × 2, +1 for ×5), `Herbs` (block break drops). Stations are `CraftStationBlock`s; the capital places one of each in `CitySouth`. The character screen (I) shows all five levels in one row.
- Crops and fish (`craft/Crops`, `craft/Fishing`): 12 crops (`CropDef`; block `<id>_crop`, `FarmCropBlock` with 4 stages that bone meal never grows, kept out of `minecraft:crops` so bees (`bee_growables`) do not grow them either; seed `<id>_seeds`, or none for radish/garlic/sweet potato which plant themselves) and 13 fish (`FishDef`); ids are saved keys. Ripe mod crops teach farming (vanilla crops never do, they take bone meal); grass gives seeds, advanced ones (chili, sesame, strawberry) only from farming level `Crops.ADVANCED_LEVEL`. `Fishing` turns `CUSTOM_SHARE` of vanilla's fishing fish into the mod's in `LootTableEvents.MODIFY_DROPS` (the hook's owner): `fishFor` picks a fish of the place first (`PLACE_CHANCE`, `Habitat` from the biome) else one found anywhere by weight; fish above the fisher's level never bite. The grocer's base list buys every crop and fish (`Crops.trades`, `Fishing.trades`) and sells the basic seeds, so `CraftPrices` values the 18 dishes from them. Icons and crop stages are drawn at datagen by `client/datagen/art/FarmArtist` (`build/farm-preview.png`). `ContentClientGameTest.checkFarming/checkFishing` cover them.
- Companions (`companion/`): `Companions` defines pets/mounts, their entity types (`pet_<id>`, `mount_<id>`), items and the owner's collection (`ModAttachments.COMPANIONS`); ids are saved keys. Pets and mounts are never saved with the world (pet types `noSave`; mount types must stay serializable because players can only ride serializable types, so `MountEntity` refuses saving itself and always counts as saddled). Flying mounts never pass a fall on to the rider, ground mounts only what a horse would feel, and leaving mid-flight saves 10 s of slow falling on the rider (`Companions.softLanding` runs before the player is written). Body plans: `client/creature/CompanionPlans` (knees are `Role.SHIN` under each leg, ears `Role.EAR`, ground mounts carry `PlanKit.saddle`; `BodyPlan.Rest` is the pose a pet takes while resting, `folds()` folds wings on the ground and tucks legs in flight — all opt-in, so monsters keep their look; `CreatureModel` gallops past `GALLOP_FROM` blocks/tick for every quadruped); item icons: `client/datagen/art/CompanionArtist`. Pets settle after their owner stands still for `PetEntity.SETTLE_TICKS` (synced `isResting`): walkers sit or lie by them, flyers land on the shoulder. Mounts: a sprinting rider runs them `MountEntity.SPRINT_BOOST` faster (`canSprint`); flyers have no jump bar (`canJump`), climb while jump is held, strafe, glide down otherwise and bank/pitch on the client (`AnimatedCreature.roll/tilt`, applied in `CreatureRenderer.setupRotations`). Particles, voices, the summon/leave bursts and each pet's reaction to its owner's kills (`Flair.Style.react`, from `Companions.afterDeath`; crouching by a pet makes it hop) live in `companion/Flair` (only `HOOVED` mounts clop like horses). Rest, wing fold and rearing are eased amounts (`AnimatedCreature.rest/wingsFolded/stand`); an empty mount never counts as flying (the client never learns an unmoved mob is on the ground). Companion skins are `shaded()` (light from above) and furry ones use `Skin.Pattern.COAT` (accent back, base belly). The manual `portraits` test (`PortraitsClientGameTest`, `-Ptests=portraits`) shoots every creature model alone from its left side without the HUD (`portrait_<id>`; pets also `_rest`, ground mounts `_rear`, named monsters `_attack`, raid bosses `_roar`): look at those after changing a plan.
- Dungeons (`dungeon/`): own dimension (`DungeonDimension`, stem written by `RaidDimensionProvider`), runs built by `DungeonLayout` (rooms along +x, pure layout, rebuilt every run), managed by `Dungeons` (nine dungeons, one opening every 10 levels from 10 to 90, ids are saved keys; the warden's `DungeonScreen` scrolls; warden `CityNpc.Role.DUNGEON_WARDEN`, keystones as the `ModDataComponents.KEYSTONE` component (a new keystone goes to a dungeon opened at most `KEYSTONE_REACH` levels below the holder), affixes by cycle, falls handled through `ALLOW_DEATH`). The boss is a `NamedMob` champion (`makeChampion`) that heals at most once per fight (`healOnlyOnce`; world bosses keep healing). Event monsters' damage multipliers live in `entity/MobPower` (read by `CombatHooks`) — never on saved data. Halls scale by `healthScale`/`partyScale`, the boss by `bossHealthScale`/`bossPartyScale`; health past `MobPower.HEALTH_CAP` (vanilla caps at 1024) becomes toughness (`MobPower.setToughness`, divided in `CombatHooks.modifyIncoming`; lords and champions through `NamedMob.capHealth`). - World events (`event/WorldEvents`): one per day at dusk (titan two days of three, invasion the third). Invaders carry `WorldEvents.INVADER_TAG`, which the city guards skip. Titans rise only near classed players of `TITAN_MIN_LEVEL`+, as a random named monster whose range holds that level, and carry `TITAN_TAG`: one that is not the running event's is removed when it loads.

## Endgame (`progress/`, `bounty/`, `enhance/`, `market/`, `talent/`)

Design notes: `docs/DESIGN-endgame.md`. `docs/ENDGAME.md` is written by `GearDocProvider` and the per-class talent tables in `docs/CLASSES.md` by `ClassDocProvider`; do not edit them by hand.

- Two reset clocks. Raids and guild bounties run on real time (`RealReset`, 0.5.5): a day starts at `RESET_HOUR` (6:00) in the server JVM's time zone, a raid cycle is 3 days; raid lockouts, raid modifiers and the three-day bounty renew per cycle, daily bounties per day. The latest day seen is saved per world (`real_reset` SavedData), so a clock turned back never resets twice; game tests jump ahead with `RealReset.skipDays`. Payloads send real time as 50 ms ticks and screens show it with `RealReset.remaining`. Everything else (lair rewards and lords, dungeon modifiers and free keystones, daily bread, world events, auction expiry) stays on the Minecraft calendar: `ResetCycle` (day = 24000 overworld clock ticks, cycle = 3 days), so lairs keep pace with play time. Bounty rewards and raid clear EXP were tripled when they moved to real time; keep that in mind before changing either clock.
- Lairs: goal chests and caches are `LairChestBlock` + `LairChestBlockEntity` with per-player, per-cycle contents (seeded by chest, player UUID and cycle; older cycles' rolls are dropped). The goal chest opens only for this cycle's victors: players within `CREDIT_RANGE` (32) of its lord when it died (`NamedMob.die` -> `lordDefeated`), plus the killer. A non-victor who comes within 20 blocks or tries to open it wakes a lord (`NamedMob.makeLord`) when none is up; a lord its chest no longer lists removes itself, and one dragged more than `LORD_LEASH` (24) blocks from its chest drops the chase and returns. The first open of a cycle counts as a lair clear (`Progress.lairCleared`).
- Raids: `RaidDifficulty` (unlock order, fee, health/damage, extra rewards), `RaidAffix` (2 per cycle, Heroic/Nightmare only), lockout keys `PlayerRecords.raidKey(boss, difficulty)` (locked members join as free practice), record table `RaidRecordsData`. The marshal screen gets cycle, modifiers and records in `OpenRaidPayload`. Gear lots are 1 + 2 per member (+ the difficulty's extra) so a party's share stays close to a solo run's; ether is graded at each member's level within the boss's range. Lair goal gear leans to the opener's class like other drops (`LairLoot.goal` gets the `JobData`).
- Kills are shared by damage (`progress/Contribution`): `LivingEntityMixin` records the health each player (or their tamed summon) really took off around `actuallyHurt`; support adds credit through `Contribution.healed/buffed/debuffed` (called from `Actions` `allyBoost`, `allyBuff`, `debuff`, and heal/zone-heal, which no content uses since 0.5.47 — new support actions should call them too); at death `Contribution.shares` lists the hitters with ≥ `MIN_SHARE` (5%), best first. Class EXP is split by share with a group bonus, the top contributor (MVP) rolls gear/pet/gold-find/essence, named coins go to wallets by share, trial kill credit and pet growth go to every contributor. - Codex, achievements and kill bounties count for each contributor and their party members within `Progress.SHARE_RANGE` (48) (`Progress.sharers`). The monster and item codex (`progress/Codex`) are records only: `ModAttachments.MONSTER_KILLS` (common monster kills by entity type id, from `Progress.afterDeath`) and `ITEMS_FOUND` (mod item paths, `Codex.scan` every second over inventory and carried bags); the client `CodexScreen` tabs read them, and `CodexSources` lists where items come from (shops, recipes, gear brackets, `screen.minecraft_mode.codex.source.<item>` lines in `CodexLang`). New mod monsters need a `Codex` place; new materials that only drop need a source line.
- Player data attachments (synced to the owner, kept on death): `RECORDS` (`PlayerRecords`: kills, clears, lockouts, achievements, title), `BOUNTY` (`BountyData` + merit), `TALENTS`. Everything that counts toward the codex, achievements and bounties goes through `Progress`; achievement and merit offer ids, bounty kinds and talent node ids (`class.branch.tier`) are saved keys — never rename them.
- Enhancement is the `ModDataComponents.ENHANCEMENT` component (level + artisan's spirit); `Enhancement.lines` feeds `GearStats`, `GearUpgrades.evolve` keeps it, names get "+N". Weapon steps +11..+14 add `EngraveStat.FINAL_DAMAGE` (`Enhancement.FINAL_PER_STEP` 2% each, 0.5.24), which `CombatHooks.outgoing` multiplies last, past every additive pool: the plain +3% basic/skill steps had sunk to about 1% each in late gear. Armor steps +11..+15 give `ARMOR_LATE_REDUCTION` (0.3% instead of 0.5%) damage reduction and `ARMOR_FINAL_PER_STEP` (0.5%) final damage. Four +15 ✦5 armor pieces give 30% damage reduction on purpose (they filled the 50% cap alone): the rest has to come from sets, engravings, options and Ironskin. The bench is `EnhanceMenu` (Artisan Brokk). Protection takes a scroll, or `EnhanceMenu.PROTECTION_ETHER` Evolution Ether of the piece's bracket or higher. `Enhancement.glow` (from +10) drives the glint (`isFoil` on class weapons/armor) and the client `EnhanceVisuals` (slot frames via `ExtractItemDecorationsCallback`, particles for held weapons and full +10 sets, `/enhanceeffects`).
- Market: `AuctionHouse` (SavedData: listings + mailboxes) and `AuctionService` (rules, fees, expiry on overworld game time, search/filter/sort/paging). Every `AuctionActionPayload` carries the viewer's `Query` and the server answers with one page (`PAGE_SIZE` 8) in `AuctionStatePayload`; text search also sends the item ids whose names match in the client's language (the server only knows English names). Filled containers/bundles and stacks over `MAX_ITEM_BYTES` cannot be listed, so a page always fits in a packet.
